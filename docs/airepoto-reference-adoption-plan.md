# Airepoto 참고 회의록 완성도 강화 계획

작성일: 2026-06-12
갱신일: 2026-06-12

## 목적

이 문서는 Airepoto를 그대로 복제하기 위한 계획이 아니다. LMO 회의 인사이트의 강점인 로컬/포터블 실행, 긴 회의 파일 처리, 대화록 편집, HWPX/DOCX/TXT/MD 내보내기를 유지하면서 회의록을 실제 보고 자료로 완성하는 계획이다.

현재 앱에는 이미 다음 기반이 있다.

- 회의 목적/정리 맥락 입력
- 대화록, 참석자 구분, 전체 요약, 주제별 정리, 참석자별 정리 상태 분리
- 전체 요약/주제별 정리/참석자별 정리 재생성
- 대화록 편집, 화자 이름 변경, 편집용 복사
- 현재 화면 기준 내보내기
- STT partial 저장, checkpoint, 이어서 분석

따라서 새 계획은 이미 있는 기능을 다시 만드는 것이 아니라, 아래 네 가지를 제품 기능으로 정리하는 데 둔다.

1. 분야별 용어를 저장/재사용한다.
2. 처음 분석은 내부 기본 처리로 기본 회의록을 만들고, 이후 후속 산출물로 확장한다.
3. 기본 회의록, 대화 보관용 회의록, 보고서용 정리 회의록을 분리한다.
4. 긴 회의 안정성 작업을 계속 진행한다.

## 제품 방향

LMO는 조직형 SaaS가 아니라 로컬 회의록 데스크탑 앱이다. 우선순위는 다음 순서로 둔다.

1. 긴 회의 파일을 안정적으로 처리하고 실패해도 대화록을 회수한다.
2. 기본 분야별 용어를 대화록 정리/보정 단계에서 선택할 수 있게 하고, 이후 사용자가 직접 추가/수정할 수 있게 한다.
3. 처음에는 내부 기본 처리로 기본 회의록을 생성하고, 이후 대화 보관용/보고서용 정리 회의록으로 이어서 가공한다.
4. 생성 결과를 기본 회의록, 대화 보관용 회의록, 보고서용 정리 회의록으로 나누어, 기록 보존용과 보고용을 구분한다.
5. 로컬 처리와 외부 모델 사용 여부를 사용자가 이해할 수 있게 설명한다.

## 1차 우선 도입

### 1. 분야별 용어 저장/재사용

전문용어와 고유명사는 매번 새 회의 화면에 길게 입력하는 방식보다, 대화록 생성 후 정리/보정 단계에서 분야별 용어로 저장해 재사용한다.

목표:

- LMO, 수산자원, 행정, 기술검토처럼 분야별 용어 묶음을 둔다.
- 회의 작성 첫 화면에는 분야별 용어 선택을 노출하지 않는다.
- 대화록 생성 후 정리/보정 단계에서 맥락 템플릿을 선택한다.
- 맥락 템플릿은 하나 이상의 용어 묶음과 정리 초점을 포함한다.
- 선택한 분야별 용어는 회의 목적/정리 맥락, 대화록 내용과 함께 표기와 의미 참고 정보로 사용한다.
- 관련 유사 표현이나 STT 오인식 후보가 있으면 표준 표기로 바꿀 수 있는 후보를 제안한다.
- STT 원문 자동 치환은 위험하므로 처음에는 직접 치환하지 않고 사람이 확인하는 후보 제안으로 시작한다.

용어 항목 구조:

- 분야: 예: LMO, 수산자원, 행정, 연구과제
- 표준 표기: 보고서에 쓸 공식 표기
- 변형/오인식 후보: STT에서 잘못 나올 수 있는 표현
- 설명: LLM이 의미를 이해하기 위한 짧은 설명
- 우선 사용처: 요약, 단어 수정, 둘 다
- 활성 여부

1차 범위:

- 기본 분야별 용어 데이터 계약과 저장 구조
- 회의 작성 첫 화면에서는 용어 선택을 제외
- 맥락 템플릿과 분야별 용어 데이터 계약
- 대화록 편집/정리 화면에서 선택 용어 기반 수정 후보를 보여줄 수 있는 설계
- 선택 용어를 후속 정리 산출물 생성 입력과 기록에 저장할 수 있는 구조

주의:

- 용어 내용은 확정 사실이 아니라 표기와 의미 힌트다.
- 대화록과 충돌하면 대화록을 우선한다.
- 자동 일괄 치환은 별도 확인 UI 없이는 적용하지 않는다.

### 2. 기본 회의록과 후속 산출물

처음 분석은 여러 산출물을 동시에 고르는 방식이 아니라 내부 기본 처리로 기본 회의록을 만든다. 대화 보관용 회의록과 보고서용 정리 회의록은 이 기본 회의록을 검토한 뒤 이어서 생성하는 후속 산출물로 둔다.

목표:

- 회의 작성 화면에는 별도 정리 기준 선택을 노출하지 않는다.
- 회의 목적/정리 맥락은 기본 회의록 생성에 먼저 반영하고, 분야별 용어는 대화록 생성 후 후속 정리/보정 단계에서 반영한다.
- 기본 회의록 생성 후 대화 보관용 회의록을 후속 단계로 생성할 수 있게 한다.
- 기본 회의록 생성 후 보고서용 정리 회의록을 후속 단계로 생성하고, 이후 HWPX/DOCX/MD 내보내기 구조에 반영한다.
- 대화 보관용 회의록과 보고서용 정리 회의록은 Ollama 같은 요약 AI가 준비되어야 생성할 수 있는 단계로 둔다.

산출물 흐름:

- 기본 회의록: 처음 생성되는 기본 결과. 개요, 주요 내용, 결정사항, 할 일을 중심으로 둔다.
- 대화 보관용 회의록: 기본 회의록 생성 후 선택한 맥락 템플릿과 대화 흐름을 바탕으로 보관/검색하기 좋게 재정리한다.
- 보고서용 정리 회의록: 기본 회의록 생성 후 선택한 맥락 템플릿과 정리 방식을 바탕으로 보고 양식에 맞춰 핵심 내용, 결정사항, 후속 조치를 다시 가공한다.

후속 산출물 항목 구조:

- 템플릿 이름
- 사용 목적
- 출력 섹션 순서
- 필수 섹션
- 선택 섹션
- 문체: 보고용, 검토용, 회의록용
- 상세도: 간결, 보통, 상세

1차 범위:

- 기본 회의록 기준은 내부값으로 회의 기록과 분석 결과 JSON에 저장한다.
- 기본 회의록 기준은 내부적으로 전체 요약 프롬프트에 반영한다.
- 이어서 분석 초안에는 내부 기본 기준을 보존하고, 분야별 용어는 후속 정리/보정 단계에서 별도로 선택한다.
- 맥락 템플릿과 회의록 정리 템플릿을 기록 정리 단계에서 선택할 수 있게 한다.
- 대화 보관용/보고서용 정리 회의록은 저장 타입과 후속 생성 개념만 잡아 둔다.

후속 범위:

- 대화 보관용 회의록 생성 UI와 저장
- 보고서용 정리 회의록 생성 UI와 다운로드 선택
- 다운로드 화면에서 기본 회의록, 대화 보관용 회의록, 보고서용 정리 회의록 중 생성된 산출물을 선택해 받을 수 있게 한다.
- Ollama 미준비 상태에서는 후속 정리 회의록 생성 버튼을 준비 필요 상태로 표시한다.
- 사용자 정의 보고 양식 저장
- 기관별 HWPX/DOCX 양식 프리셋
- 내보내기 파일 섹션 순서에 보고 양식 반영
- 보고 양식별 검증 샘플 추가

### 3. 기본 회의록, 대화 보관용 회의록, 보고서용 정리 회의록 분리

산출물은 세 가지 형태로 나눈다. 모두 회의 내용을 기반으로 하지만 목적과 가공 수준이 다르다.

기본 회의록:

- 분석 직후 내부 기본 처리로 생성되는 결과다.
- STT와 참석자 구분 결과를 바탕으로 개요, 주요 내용, 결정사항, 할 일을 만든다.
- 사용자가 대화록을 검토하고 화자명/단어/발언 내용을 수정하는 기준 자료다.
- 후속 산출물 생성의 입력으로 사용한다.

대화 보관용 회의록:

- 기본 회의록과 수정된 대화록을 바탕으로 이어서 생성한다.
- Ollama 같은 요약 AI가 준비되어야 생성할 수 있다.
- 불필요한 내부 메타 정보, 검토용 표시, 분석 상태는 제외한다.
- 사람 이름과 발언 내용은 회의 진행 기록으로 읽을 수 있는 수준으로 남긴다.
- 보고 양식 문서가 아니라 대화 흐름 보관과 검색에 맞춘 회의록이다.

보고서용 정리 회의록:

- 기본 회의록 또는 대화 보관용 회의록을 바탕으로 AI가 다시 정리한 보고용 산출물이다.
- Ollama 같은 요약 AI가 준비되어야 생성할 수 있다.
- 선택한 보고 양식의 섹션, 문체, 상세도, 순서에 맞춰 재가공한다.
- 심사/검토 보고, 요약 보고, 기관 제출용 문서처럼 목적별 양식이 달라질 수 있다.
- 회의록을 근거로 만든 보고 가능 형태의 정리 회의록이다.

1차 범위:

- 회의 기록에 `기본 회의록`, `대화 보관용 회의록`, `보고서용 정리 회의록` 산출물 개념과 저장 타입을 둔다.
- 대화록 편집, 화자명 변경, 단어 수정은 기본 회의록과 후속 산출물의 입력을 다듬는 작업으로 본다.
- 대화 보관용 회의록과 보고서용 정리 회의록은 실제 생성 UI와 다운로드 선택을 후속 구현으로 둔다.
- Ollama가 없거나 정리 모델이 준비되지 않은 PC에서는 기본 회의록과 대화록 다운로드까지 완료하고, 후속 정리 회의록은 나중에 생성하도록 둔다.

후속 범위:

- 기본 회의록과 대화 보관용 회의록 비교
- 대화 보관용 회의록 생성 UI와 저장
- 보고서용 정리 회의록 생성 UI와 다운로드 선택
- 대화 보관용 회의록 잠금/해제
- 보고서용 정리 회의록 재생성 전 경고
- 보고 양식별 미리보기

### 4. 긴 회의 안정성 계속 진행

긴 회의 안정성은 새 계획의 핵심 유지 항목이다. 이미 checkpoint, partial transcript, 이어서 분석, 참석자 구분 재사용 기반이 있으므로 다음 작업은 검증과 보강이다.

남은 작업:

- 30분, 1시간, 2시간 이상 샘플에서 실제 처리 시간과 실패 지점을 기록한다.
- STT partial 결과가 참석자 구분/요약 실패 이후에도 회수되는지 확인한다.
- 이어서 분석이 같은 파일/같은 설정에서만 동작하는지 확인한다.
- 참석자 구분 장시간 구간에서 UI가 멈춘 것처럼 보이지 않게 유지한다.
- 시간 범위 누락/중복을 샘플 결과에서 점검한다.
- 요약 실패 시 대화록과 기본 문서 내보내기가 가능한지 확인한다.

기준:

- 긴 파일 실패가 전체 실패로 끝나지 않아야 한다.
- 이미 끝난 음성 인식 구간은 가능하면 다시 돌리지 않는다.
- 사용자는 지금 볼 수 있는 결과와 아직 진행/실패한 단계를 구분할 수 있어야 한다.

## 2차 제품 완성도 강화

### 0. 2026-06-12 1차 구현 상태

- 내부 기본 회의록 기준과 기본 분야별 용어 계약을 `desktop-app/src/meetingKnowledge.ts`에 추가했다.
- 새 회의록 작성 화면에서는 정리 기준과 분야별 용어 선택을 모두 노출하지 않는다.
- 내부 기본 회의록 기준은 이어서 분석 초안, `/api/analyze` 요청, 백엔드 result JSON, 프론트 회의 기록에 저장하도록 연결했다.
- 전체 요약 프롬프트는 내부 기본 회의록 기준과 회의 목적/정리 맥락을 참고 정보로 받는다.
- 분야별 용어는 대화록 생성 후 단어 수정 후보, 대화 보관용 회의록, 보고서용 정리 회의록 단계에서 선택/적용하는 후속 기능으로 둔다.
- 기록 정리 단계에 맥락 템플릿과 회의록 정리 템플릿 선택 UI를 추가했다. 현재는 선택값 저장까지이며, 실제 후속 생성 연결은 남아 있다.
- 후속 생성에 연결하기 전에 템플릿/용어 버전 규칙을 정한다. 기본 원칙 후보는 회의 당시 스냅샷으로 재현하고, 최신 용어 기준 재생성은 사용자가 명시적으로 선택하게 하는 방식이다.
- 내부 기본 회의록 작성 기준과 후속 회의록 정리 템플릿은 코드 타입/이름을 분리해 기본 회의록, 대화 보관용 회의록, 보고서용 정리 회의록이 섞이지 않게 한다.
- 아직 용어 관리 UI, 대화 보관용 회의록 생성, 보고서용 정리 회의록 생성, 보고 양식별 내보내기 섹션 재배치는 남아 있다.

### 1. 단어 수정 제안

선택한 용어를 기반으로 대화록에서 의심 표현을 찾아 제안한다.

- 자동 일괄 수정이 아니라 후보 표시와 수동 적용을 우선한다.
- 변경 전/후를 보여준다.
- 보고서용 정리 회의록 생성 전 확인 단계로 연결한다.

### 2. 후속 산출물별 재생성

전체 분석을 다시 돌리지 않고 다음만 따로 재생성한다.

- 전체 요약
- 주제별 정리
- 참석자별 정리
- 대화 보관용 회의록
- 보고서용 정리 회의록
- 문서 파일

### 3. 로컬 보안/데이터 흐름 안내

인증이나 보안 수준을 과장하지 않고, 실제 동작 기준으로 안내한다.

- 음성 파일 저장 위치
- 결과 파일 저장 위치
- 외부 AI 사용 여부
- Ollama/로컬 모델 사용 여부
- 삭제 방법
- 회사 PC/오프라인 PC에서 가능한 기능과 제한

## 나중 도입 후보

현실적으로 검토할 후보는 제한적으로 둔다.

### 1. 공유

우선은 직접 Slack/이메일 연동보다 다음 기능이 먼저다.

- 파일 위치 열기
- 복사용 보고 요약
- HWPX/DOCX/PDF 등 제출용 문서 품질 개선

직접 공유 연동은 반복 요구가 확인된 뒤 검토한다.

### 2. 모바일

독립 모바일 앱은 현재 범위 밖이다. 대신 다음 정도만 후보로 둔다.

- 휴대폰 녹음 파일을 PC로 옮겨 업로드하는 안내
- 모바일 녹음 파일 형식 호환성 개선
- 여러 파일 업로드와 순차 분석

## 실행 순서

1. 용어 데이터 구조와 저장 위치를 정한다.
2. 기본 회의록 기준은 내부값으로 고정하고 저장 구조를 정한다.
3. 회의 작성 화면에는 정리 기준과 분야별 용어 선택을 노출하지 않는다.
4. 대화록 생성 후 기록 정리 단계에서 맥락 템플릿과 회의록 정리 템플릿을 선택할 수 있게 한다.
5. 기본 회의록, 대화 보관용 회의록, 보고서용 정리 회의록 산출물 구조를 만든다.
6. 다운로드에서 생성된 산출물과 파일 형식을 선택할 수 있게 한다.
7. 긴 회의 안정성 검증과 보강을 계속 진행한다.
8. 로컬 보안/데이터 흐름 안내를 설정 또는 도움말 화면에 정리한다.
