바로록 프로덕션 디자인 구현 인계

이미지 시안의 완성도를 유지하면서 실제 기능, 상태 복구, 접근성과 반응형 계약을 깨뜨리지 않기 위한 구조 우선 구현 기준입니다.

준비 상태 · 구현 시작 가능

결정

JSON은 필요하지만 좌표 명세로 사용하지 않습니다.

ui-structure.json은 공통 영역의 소유권, 화면별 상태, 실제 기능 계약과 검증 기준을 고정합니다. PNG는 시각 비교 기준이고 React 컴포넌트와 CSS 토큰이 실제 구현물입니다.

시각 기준여섯 PNG의 앱 프레임, 위계, 밀도, 표면과 색
동작 기준현재 React 상태, 저장소, 분석, 복구, 내보내기 계약
충돌 기준기능과 접근성이 이미지보다 우선하며 차이는 검증 기록에 남김

구조

공통 앱 셸

Layout, Header, Sidebar가 모든 화면의 프레임과 탐색을 한 번만 소유합니다.

작성 상태군

MeetingWriter가 새 기록과 분석 진행을 소유하되 입력·진행 프레젠테이션 영역을 분리합니다.

상세 공통 프레임

제목, 메타, 재생기, 상태 칩, 탭과 검색은 세 상세 탭이 공유합니다.

설정 대화상자

Settings의 상태 로직은 유지하고 일반·모델 탭의 행 구조와 표면만 정돈합니다.

화면 명세

01

새 기록

업로드와 회의 정보를 2열로 묶고 실행부는 두 열을 가로지르는 하나의 하단 행으로 둡니다.

02

분석 진행

파일 식별, 실제 단계, 진행률, 상태 상세와 중지·취소 복구를 같은 작업면에 배치합니다.

03

대화록

본문을 카드 중첩이 아닌 열린 스캔 목록으로 유지하고 hover 편집 도구는 자리를 미리 확보합니다.

04

기록 정리

문서 본문과 후속 조치 표를 중심으로 두고 키워드는 좁은 보조 레일로 낮춥니다.

05

보고서

명령 모음과 인쇄 미리보기 표면을 분리하고 현재 지원하는 파일 형식만 표시합니다.

06

설정

일반·모델 두 탭만 유지하고 파일·분석·보관·문제 해결 행을 일관된 밀도로 구성합니다.

구현 순서

  1. 배경 패턴, 앱 프레임, 표면, 여백, 타이포그래피 토큰을 고정합니다.
  2. 기존 LMO·Refero·Barorok 팔레트에 새 색상군을 더하지 않고 Barorok 의미 토큰으로 별칭을 정리합니다.
  3. 헤더와 사이드바를 기준 이미지에 맞추되 기존 폴더·회의록·분석 상태 동작을 보존합니다.
  4. 새 기록과 분석 진행을 같은 작성 상태군으로 정리합니다.
  5. 회의 상세 공통 프레임을 한 번 만든 뒤 대화록, 기록 정리, 보고서 본문을 끼웁니다.
  6. 설정 대화상자의 공통 행과 상태 표면을 정리합니다.
  7. 화면별 캡처 비교와 좁은 시뮬레이션을 통과한 뒤 다음 화면으로 넘어갑니다.

탭마다 명령 모음 높이와 정렬이 달라짐중복 위험 높음DetailCommandBar 변형으로 통일
새 기록과 분석 진행을 별도 페이지로 복제불필요MeetingWriter 상태 변형으로 유지
시안의 진행 단계와 저장 형식을 그대로 추가기능 충돌실제 백엔드 단계와 지원 형식만 렌더링
기존 세 팔레트 위에 새 디자인 색상 추가토큰 중복Barorok 의미 토큰으로 통합하고 화면은 의미 토큰만 참조
화면마다 해양 배경 강도 다름일관성 문제01·05 수준의 낮은 대비 패턴 하나만 사용
성공 안내가 레이아웃을 밀어냄회귀 위험토스트 또는 예약된 상태 칩 사용

검증

  • 1536×1024에서 기준 PNG와 구조·위계·밀도를 비교합니다.
  • 1280×720과 1024×720에서 주 동작 노출과 가로 overflow 0을 확인합니다.
  • 각 단계에서 typecheck, 변경 파일 lint, 관련 Playwright 시뮬레이션, diff --check를 실행합니다.
  • loading, error, stalled, stale, disabled, focus와 키보드 상태를 정상 화면과 별도로 확인합니다.
  • P0·P1과 현재 디자인 목표를 막는 P2가 없으면 준비된 화면 단위를 종료합니다.
