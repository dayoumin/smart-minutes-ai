# 2026 제품형 UI/UX 현대화 계획

작성일: 2026-06-15

## 목적

현재 앱은 회의록 작성, 대화록, 기록 정리, 보고서 생성의 기능 구조는 갖췄지만 시각 완성도는 아직 내부 업무 도구에 가깝다. 이 계획은 2026년 기준의 유명 업무형 제품처럼 보이도록 화면 구조, command bar, 작업면, 대화록 읽기 경험, 상태 전환을 단계적으로 개선하기 위한 실행 기준이다.

## 현재 진단

### 잘 된 점

- 좌측 회의 목록, 새 회의록 작성, 회의 상세의 큰 정보 구조는 이해 가능하다.
- `대화록`, `기록 정리`, `보고서`의 3단계 산출물 구분은 사용자 의도와 맞다.
- 정리 맥락과 보고 양식이 각각 정리/보고서 단계에 붙는 방향은 맞다.
- 버튼 문구와 내부 구현 용어 노출은 이전보다 줄었다.
- 토스트/비레이아웃 시프트 알림 원칙은 적용되기 시작했다.

### 부족한 점

- 넓은 화면에서 작업면을 충분히 쓰지 못하고, 중앙 카드가 떠 보인다.
- 상세 화면 상단 메타 정보, 탭, 본문, 액션이 하나의 제품 표면처럼 이어지지 않는다.
- `기록 정리`와 `보고서`의 실행 컨트롤은 기능상 맞지만 command bar로 보이지 않는다.
- 대화록은 텍스트 리스트에 가까워 긴 회의록을 반복해서 읽는 제품감이 약하다.
- 회의 선택/전환 시 큰 빈 카드와 단문 로딩이 나타나 최신 제품형 skeleton 전환과 거리가 있다.
- 첫 화면의 새 회의록 작성 폼은 안정적이지만, 주요 작업 흐름과 CTA 위계가 약하다.

## 현대화 원칙

- 작업 표면을 넓게 쓴다. 넓은 데스크톱에서 큰 여백만 남기는 중앙 카드 구성을 피한다.
- 상단 메타, 탭, command bar, 본문은 같은 흐름의 작업면으로 보이게 한다.
- 주요 실행 버튼은 해당 탭의 command bar에 두고, 관련 선택값과 한 줄에 묶는다.
- 결과 본문은 장시간 읽기 기준으로 설계한다. 행 간격, speaker chip, 시간, 발언 텍스트를 분리한다.
- 일시 상태는 toast나 overlay로, 전환 상태는 skeleton으로, 복구가 필요한 상태는 inline으로 둔다.
- 모달은 사용자가 현재 작업을 멈추고 저장해야 하는 설정에만 쓴다. 짧은 선택/명령은 메뉴나 command bar에서 처리한다.
- 시각 스타일은 한 가지 색 계열에 기대지 않고, 중립 배경, 명확한 accent, 섬세한 hover/focus 상태로 구성한다.

## 범위

### 1차 범위

- 새 회의록 작성 화면
- 회의 상세 상단 작업면
- `대화록`, `기록 정리`, `보고서` 탭
- 회의 선택/탭 전환 로딩 상태
- 공통 button, tab, command bar, select/menu 스타일

### 1차 제외

- 공유, 모바일 전용 UI
- 조직 권한, 팀 워크스페이스, 관리자 기능
- 보고서 다운로드/HWPX 양식 완전 반영
- 전체 설정 화면 리디자인
- 새 기능 추가를 전제로 한 화면 개편

## 실행 단계

### P1-1. 상세 화면 작업면 재구성

목표:

- 큰 카드 하나에 모든 것을 넣은 느낌을 줄인다.
- 상단 회의 정보, 처리 상태, 탭, 검색, 본문이 자연스럽게 이어지게 한다.

작업:

- 상세 화면 container 폭과 정렬을 재검토한다.
- 상단 메타 정보는 더 압축하고, 본문 작업 영역에 시각적 우선순위를 준다.
- 탭과 검색을 같은 레벨의 navigation/action 영역으로 정리한다.
- 회의 정보 수정 버튼은 상단 오른쪽에 두되 주변 여백과 hover 상태를 정리한다.

완료 기준:

- 1440px 이상 데스크톱에서 본문 작업면이 과도하게 좁아 보이지 않는다.
- 상단 메타 정보가 본문보다 더 큰 시각 비중을 차지하지 않는다.
- 대화록/기록 정리/보고서 탭 전환 시 상단 구조가 흔들리지 않는다.

### P1-2. 기록 정리/보고서 command bar 통합

목표:

- 정리 탭과 보고서 탭의 선택값, 메뉴, 실행, 저장 버튼이 하나의 command bar처럼 보이게 한다.

작업:

- `전체 요약`, `주제별 정리`, `참석자별 정리` 탭 오른쪽에 정리 기준, 메뉴, 다시 정리, 저장을 정렬한다.
- 보고서 탭의 보고 양식, 메뉴, 생성 버튼도 같은 command bar 패턴을 사용한다.
- select 라벨, 메뉴 버튼, 실행 버튼 높이와 radius를 통일한다.
- 버튼 문구는 짧게 유지하고, 긴 설명은 tooltip/title 또는 보조문으로 분리한다.

완료 기준:

- 사용자가 “무엇을 선택하고 무엇을 실행하는지” 한 줄에서 이해한다.
- 같은 종류의 액션이 탭마다 같은 위치와 크기로 나타난다.
- command bar가 본문 카드와 따로 노는 느낌이 없다.

### P1-3. 첫 화면 새 회의록 작성 플로우 개선

목표:

- 새 회의록 작성 화면을 단순 입력 폼이 아니라 회의 정보 입력, 파일 선택, 분석 시작으로 이어지는 작업 흐름으로 보이게 한다.

작업:

- 회의 정보 입력, 파일 선택, 참석자 구분, 분석 시작이 자연스럽게 이어지도록 입력 흐름과 CTA 위계를 정리한다.
- 파일 드롭 영역의 비중과 affordance를 강화한다.
- `오디오 추출`, `참석자 구분`, `분석 시작`의 주/부 액션 위계를 명확히 한다.
- 넓은 화면에서 카드가 너무 작게 떠 보이지 않게 폭과 배치를 조정한다.

완료 기준:

- 사용자는 처음 화면에서 다음 행동을 바로 알 수 있다.
- 파일 선택 전/후 레이아웃이 크게 흔들리지 않는다.
- 분석 시작 버튼이 화면의 명확한 primary action으로 보인다.

### P2-1. 대화록 리스트 가독성 개선

목표:

- 긴 회의록을 읽고 편집하기 좋은 transcript 제품 경험으로 만든다.

작업:

- speaker chip, 시간 범위, 상태 배지, 발언 텍스트의 위계를 분리한다.
- 긴 발화와 짧은 발화가 모두 안정적으로 보이게 행 패턴을 조정한다.
- 대화록 액션 버튼은 본문을 방해하지 않도록 command area에 모은다.
- 편집 모드, 검색 결과, 참석자 확인 필요 상태를 같은 행 시스템 안에서 처리한다.

완료 기준:

- 발언자가 바뀌는 지점이 빠르게 스캔된다.
- 긴 발언도 단락처럼 읽히고, 짧은 발언도 과도하게 큰 빈 공간을 만들지 않는다.
- 편집/복사/저장/이름 변경 액션이 본문과 섞이지 않는다.

### P2-2. 로딩과 전환 상태 개선

목표:

- 회의 선택, 탭 전환, 생성 진행 중에도 화면 구조가 안정적으로 유지되게 한다.

작업:

- 회의 상세 로딩을 큰 빈 카드 대신 skeleton header와 skeleton rows로 바꾼다.
- 탭 전환 시 command bar 높이를 유지한다.
- 생성 중 상태는 버튼 spinner와 최소한의 상태 텍스트로 표시한다.
- 성공/완료 알림은 레이아웃을 밀지 않는 toast나 고정 overlay로 제한한다.

완료 기준:

- 회의 선택 직후에도 사용자는 어떤 화면이 로딩 중인지 알 수 있다.
- 상단 탭/command bar가 로딩 중에도 위치를 유지한다.
- 일시 알림 때문에 본문이 아래로 밀리지 않는다.

### P2-3. 미세 스타일 정리

목표:

- 반복 UI 요소가 하나의 제품 디자인 시스템으로 느껴지게 한다.

작업:

- tab active, hover, focus, disabled 상태를 통일한다.
- menu, modal, select, icon button의 radius와 shadow를 맞춘다.
- 원시 색상 유틸 사용을 줄이고 semantic token 중심으로 옮긴다.
- 카드 안 카드처럼 보이는 중첩 구조를 줄인다.

완료 기준:

- 같은 역할의 버튼과 메뉴가 화면마다 같은 느낌으로 보인다.
- focus ring과 hover가 과하지 않고 명확하다.
- 색상과 그림자가 한 화면에서 산만하게 경쟁하지 않는다.

## 검증 계획

- 브라우저 확인: 새 회의록 작성, 대화록, 기록 정리, 보고서 화면을 데스크톱 폭에서 확인한다.
- 좁은 화면 확인: 최소 1024px 폭에서 overflow와 버튼 줄바꿈을 확인한다.
- 자동 검증: `corepack pnpm --dir desktop-app typecheck`.
- 필요 시 시뮬레이션: 변경 범위가 다운로드/생성 상태에 닿으면 관련 `desktop-app/scripts/simulate-*.mjs`만 실행한다.
- 시각 기준: screenshot으로 상단 작업면, command bar, 대화록 리스트가 레이아웃 시프트 없이 보이는지 확인한다.

## 보류 항목

- 모바일 최적화는 데스크톱 작업면 안정화 후 별도 계획으로 다룬다.
- 보고서 다운로드와 양식별 HWPX/DOCX 반영은 보고서 생성 흐름 안정화 후 진행한다.
- 공유, 팀, 권한, 관리자 기능은 현재 제품 범위에서 제외하고 `roadmap.md`에만 둔다.
