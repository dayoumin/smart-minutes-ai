PRODUCT REDESIGN · 2026-07-29

하나의 바로록 화면을 데스크톱과 웹에서 사용한다

현재 기능과 데이터 계약을 보존하면서 해양·수산 정체성을 가진 1인용 기록 제품으로 전면 전환한다. 화면 코드를 복제하지 않고 같은 React UI를 유지하며, 웹 UI와 사용자가 내려받는 로컬 엔진을 첫 제품 구현으로 우선한다.

이번에 확정할 결정

확정

현재 로컬 브랜치에서 바로 수정

codex/barorok-desktop-web-redesign에서 작업한다. 이미 실행 중인 개발 서버를 사용해 작은 화면 단위로 즉시 비교한다.

확정

데스크톱·웹 UI는 하나

기존 desktop-app의 React UI를 공통 제품 화면으로 유지한다. 별도 web-app 복제본은 만들지 않는다.

확정

1인용 제품으로 제한

조직, 초대, 권한, 공유, 과금, 공동 편집을 만들지 않는다. 개인 기록, 분석, 정리, 보고서, 검색과 설정에 집중한다.

확정

웹·로컬 실행 우선

HTTPS 웹 UI를 먼저 제공하고 사용자가 내려받은 Windows 로컬 엔진에서 분석·저장·모델 실행을 처리한다. 데스크톱 portable 검증은 웹 착수 조건이 아니라 공통 UI와 계약을 재사용하는 후속 호환 단계로 둔다.

사용자 승인 시안 채택 기준

2026-07-29에 검토한 네 개의 밝은 데스크톱 시안을 앞선 마케팅형 해양 대시보드보다 우선한다. 시각 언어와 화면 밀도는 참고하되, 시안 속 가상 기능은 현재 제품 요구로 간주하지 않는다.

시안 역할 채택 현재 제품에 맞춘 수정
새 기록 파일 등록, 최근 기록, 밝은 앱 셸 현재 회의 정보, 분석 옵션, 이어하기 기능을 유지한다.
분석 진행 파일 정보, 진행률, 예상 시간, 상태 요약 대화록 우선 흐름을 표시하고 참석자 구분·정리·보고서를 자동 고정 단계처럼 보이지 않는다.
회의 상세 제목·메타·동작 위계와 넓은 작업면 대화록, 기록 정리, 보고서의 현재 세 탭을 유지한다.
설정 밝은 표면, 조밀한 행, 명확한 상태 실제로 존재하는 파일·분석·보관·문제 해결 옵션만 표시한다.

작업 계약

목표 바로록을 상용 제품 수준의 해양·수산 특화 개인 회의 기록 도구로 보이게 한다.
우려 전면 디자인 변경이 기존 분석, 이어하기, 편집, 생성, 저장과 내보내기를 깨뜨릴 수 있다.
첫 범위 브랜드 토큰과 제한된 앱 프레임, 왼쪽 기록 목록, 오른쪽 새 기록 작업면. 기능 추가보다 기존 기능의 재배치에 집중한다.
보호선 백엔드 출력 계약과 MeetingRecord를 유지하고, SaaS·모바일·순수 브라우저 AI를 끌어들이지 않는다.
검증 타입 검사, 변경 파일 lint, 관련 Playwright 시뮬레이션, 1024/1280/1440/1920px 시각 확인.
중단 조건 한 화면이 기존 기능을 유지하고 자동·시각 검증을 통과하면 다음 화면으로 넘어간다. 무기한 미세 조정하지 않는다.

제품 화면과 기능 범위

시안에 보이는 요소를 그대로 기능 요구로 간주하지 않는다. 현재 구현된 기능을 새 정보 구조에 배치하고, 새로운 기능은 실제 1인 사용 흐름에 필요한 경우에만 별도 결정한다.

왼쪽 기록 탐색

  • 새 기록 시작
  • 분석 중·이어하기
  • 폴더 만들기와 회의록 분류
  • 최근·전체 회의록 목록

새 기록

  • 회의 정보 입력
  • 음성 파일 선택
  • 분석 옵션과 준비 상태
  • 분석 시작·중지·이어하기

회의 작업 공간

  • 음성 재생과 검색
  • 대화록 확인·편집
  • 기록 정리와 보고서
  • 참석자·결정·후속 작업

설정

  • 파일과 보관
  • 분석 기본값
  • 모델 준비 상태
  • 문제 해결

코드와 자산 구조

기존 대형 컴포넌트를 한 번에 이동하지 않는다. 새 셸과 새 화면 조각을 먼저 만들고, 검증된 단위만 점진적으로 추출한다.

해양 이미지는 공통 헤더, 새 기록의 빈 상태, 회의 상세의 얇은 상단 띠처럼 제한된 영역에만 사용한다. 대화록·정리·보고서 본문은 불투명한 작업면을 유지한다. 이미지 안에는 로고나 문구를 굽지 않는다.
데스크톱에서는 앱 전체를 최대 1360px 프레임 안에 중앙 정렬하고, 화면 크기에 따라 좌우 16~48px와 상하 16~32px의 유동 여백을 둔다. 왼쪽 256~288px는 기록 탐색, 오른쪽은 현재 작업 하나만 소유한다. 1024px 이하에서만 프레임이 화면을 채운다.

단계별 실행

1

브랜드 기반

사용자 표시명을 바로록으로 정리하고 색상·간격·표면·해양 이미지 토큰을 만든다. 내부 패키지명과 경로는 당장 바꾸지 않는다.

2

앱 셸과 기록 탐색

제한된 데스크톱 프레임을 만들고 왼쪽에 폴더·회의록 목록·분석 상태, 오른쪽에 현재 새 기록 작업면을 둔다. 회의록 목록은 오른쪽에 중복하지 않는다.

3

새 기록 기본 화면

참고 이미지의 밝고 집중된 파일 등록 구도를 적용하고 회의 정보와 분석 시작 동작을 유지한다. 낮은 창에서는 업로드 영역을 가로형으로 압축한다.

4

분석 진행

대화록 우선 흐름, 진행률, 경과 시간, 중지·취소·이어하기를 같은 작업면 안에서 안정적으로 표시한다.

5

회의 상세와 산출물

상단 메타와 재생기, 대화록·기록 정리·보고서 탭을 같은 command bar와 결과 표면 체계로 맞춘다. 기존 편집·생성·저장 계약을 유지한다.

6

웹 로컬 엔진 MVP

같은 UI를 HTTPS 웹과 Windows 로컬 엔진에 연결한다. 설치, 페어링, API 인증, 로컬 저장과 업데이트를 검증한다.

7

데스크톱 호환과 후속 제공

웹에서 검증한 공통 UI와 로컬 실행 계약을 데스크톱에 재사용하고, 실제 포터블 앱의 배포·파일 시스템·종료 흐름을 별도로 확인한다.

화면별 완료 기준

확인 영역 자동 확인 시각·사용 확인
공통 typecheck, 변경 파일 lint, diff --check 1024/1280/1440/1920px, 가로 넘침 0, 키보드 포커스

웹 build:web, 연결·인증 집중 테스트 Chrome/Edge Local Network Access 승인·거부·복구

브랜치와 커밋 전략

  • 현재 작업 브랜치는 codex/barorok-desktop-web-redesign 하나를 사용한다.
  • 현재 미커밋 백엔드 기본값 수정과 UI 수정은 커밋할 때 의미별로 분리한다.
  • 브랜드 기반, 앱 셸·새 기록, 회의 상세처럼 검증 가능한 화면 단위로 커밋한다.
  • 데스크톱과 웹을 장기 브랜치로 분리하지 않는다. 같은 UI의 회귀 수정이 갈라지는 것을 막는다.
  • 웹 로컬 엔진을 실제로 시작할 때는 깨끗한 기준에서 별도 브랜치나 worktree를 사용한다.
  • 병합 전 큰 관점과 작은 관점의 agent 검토를 수행하고, 현재 흐름을 막는 문제만 즉시 수정한다.
