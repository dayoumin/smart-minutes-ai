# 바로록 새 회의록 — 고래·햇빛 테마 레이아웃 고정 사양

상태: 선택 디자인의 구현 기준

최종 시각 기준:

- `new-record-whale-tail-selected-no-footer.png`

관련 탐색 기록:

- `new-record-ocean-theme-variants-plan.md`

## 1. 문서의 역할

이 파일은 새 회의록의 고래·햇빛 테마를 실제 화면으로 옮길 때 레이아웃과 배경 배치가 흔들리지 않게 하는 기준이다.

구현자는 UI가 포함된 합성 시안의 픽셀을 그대로 배경으로 사용하지 않는다. 시안은 최종 인상과 상대적 비율을 판단하는 기준이며, 실제 화면은 다음 네 층으로 나눈다.

```text
앱 셸
  ├─ 고정 사이드바
  └─ 해양 작업 캔버스
       ├─ UI가 제거된 WebP 배경판: 바다색, 수면광, 고래, 해저 풍경
       ├─ CSS 대비 오버레이와 단색 fallback
       ├─ 작업 UI: 제목, 업로드, 회의 정보, 분석 시작
       └─ 상호작용 효과: 업로드 물결, 버튼 내부 물결
```

## 2. 적용 우선순위와 변경 금지 기준

이 사양은 `docs/design.md`의 `새 회의록 고래·햇빛 테마 파일럿 예외`에 의해 `minutes` 작업 영역에서만 일반 프레임 규칙보다 우선한다. 다른 탭에는 적용하지 않는다.

- `minutes` 작업 동안 앱은 전체 창을 채운다. 새 기록에서 분석 진행으로 전환돼도 shell geometry를 바꾸지 않는다.
- 이 문서의 새 기록 작업 레일은 `MeetingWriter`의 입력·이어하기 상태에서만 표시한다. WebP 배경판은 시작·입력·분석 진행에서 같은 `ocean` 셸에 유지하고, 분석 진행에서는 CSS 대비 오버레이를 강화해 장면을 낮은 대비로 만든다. 기존 진행 화면 내부 구조는 유지한다.
- 사이드바와 해양 작업 캔버스 사이에 별도 외곽 여백을 두지 않는다.
- 업로드 영역과 회의 정보 영역은 1600px 이상에서 계속 커지지 않는다.
- 화면이 넓어질 때는 UI가 늘어나는 대신 바다 배경의 여유 공간이 더 보인다.
- 별도 하단 실행 카드, 흰 바닥 영역, 상단 구분선은 만들지 않는다.
- `분석 시작` 버튼은 해양 작업 캔버스 위에 직접 둔다.
- 버튼은 `220–240px` 폭으로 유지하고 오른쪽 끝은 회의 정보 패널의 오른쪽 끝선과 일치한다.
- 수심, 좌표, 해도 눈금, 등심선은 사용하지 않는다.
- 고래·물고기·산호는 배경판의 안전 영역 안에서 입력 필드나 버튼 위에 겹치지 않는다.
- 사이드바·글자·버튼·카드가 포함된 합성 기준 이미지 전체를 런타임 배경으로 사용하지 않는다.

## 3. 기준 좌표계

레이아웃의 반응형 기준은 viewport가 아니라 기존 사이드바를 제외한 해양 작업 캔버스의 `inline-size`다. viewport 표는 검증 예시일 뿐 CSS 분기의 원본으로 사용하지 않는다.

- 기존 사이드바 실제 폭 `272px`를 유지한다.
- 해양 캔버스에 `container-type: inline-size`를 둔다.
- minutes-scoped shell variant에서는 외부 앱 프레임 여백과 workspace padding을 제거한다.
- 이 variant의 workspace 자체 `overflow`는 제거하고 해양 캔버스 하나만 `overflow-y: auto`를 소유한다.
- 회의 상세로 이동하면 기존 최대 1360px 앱 프레임과 workspace padding 규칙으로 돌아간다. 설정은 현재 작업면 위의 modal overlay이므로 설정을 열어도 아래 셸 geometry는 바뀌지 않는다.

### 공통 축

```text
viewport
├─ sidebar
└─ ocean canvas
   ├─ content inset left
   ├─ fixed work rail
   │  ├─ upload panel
   │  ├─ column gap
   │  └─ meeting panel
   └─ ambient scene remainder
```

작업 레일은 해양 캔버스의 정확한 중앙이 아니라 약간 왼쪽에 둔다. 오른쪽에는 고래와 산호가 보일 환경 여백을 더 남긴다.

## 4. 너비 사양

| Viewport 예시 | Sidebar | Ocean canvas | 왼쪽 inset | Work rail | Upload | Gap | Meeting | 오른쪽 환경 여백 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1024 | 272 | 752 | 24 | 704, 한 열 | 704 | 16 | 704 | 24 |
| 1280 | 272 | 1008 | 28 | 880 | 488 | 24 | 368 | 100 |
| 1440 | 272 | 1168 | 32 | 976 | 536 | 24 | 416 | 160 |
| 1600+ | 272 | 나머지 | 40 | 1056 max | 584 max | 24 | 448 max | 나머지 전부 |

### 적용 규칙

- `work rail`의 최대 폭은 `1056px`이다.
- 업로드와 회의 정보의 기준 비율은 약 `55:43`이다.
- 캔버스 `832px 이상`에서는 작업 레일 폭을 `min(1056px, calc(60cqi + 275.2px))`로 계산한다. 이 식은 캔버스 `1008 / 1168 / 1328px`에서 각각 약 `880 / 976 / 1056px`가 된다.
- 2열의 업로드 폭은 `min(584px, calc(30cqi + 185.6px))`로 계산하고, 회의 정보 폭은 `work rail - upload - 24px`로 계산한다. 캔버스 `1008 / 1168 / 1328px`에서 각각 `488 / 536 / 584px`와 `368 / 416 / 448px`가 되어 표와 정확히 일치한다. 캔버스 `832px`에서 회의 정보 폭은 약 `315px`이며 이것을 2열의 실질 최소 폭으로 본다.
- 작업 레일의 왼쪽 inset은 캔버스 `832–1055px: 28px`, `1056–1247px: 32px`, `1248px 이상: 40px`로 고정한다. 남는 폭은 오른쪽 환경 여백이 소유한다.
- 캔버스 `832px 미만`에서는 한 열로 전환한다. 1024px viewport는 기존 272px 사이드바를 제외하면 752px이므로 한 열이다.
- 오른쪽 환경 여백은 최소값이 아니라 남는 공간이다. UI 패널을 늘려 이 공간을 소비하지 않는다.

### 한 열 계약

- 순서: 제목 → 업로드 → 회의 정보 → 분석 시작.
- 작업 레일 폭은 `min(100% - 48px, 704px)`이며 캔버스 안에서 중앙 정렬한다.
- 업로드 높이는 `220–260px`, 회의 정보는 내용 기반 `min-height: 360px`를 사용한다.
- 분석 버튼은 회의 정보 패널 폭 전체를 차지하지 않고 `220–240px`로 유지하며 오른쪽에 정렬한다.
- 환경 장면은 고래의 일부 실루엣과 수면광만 남기고 물고기·산호는 숨긴다.
- 해양 캔버스가 세로 스크롤을 소유한다. 패널 내부에 별도 세로 스크롤을 만들지 않는다.
- 한 열에서는 workspace 높이와 무관하게 캔버스의 연속 세로 스크롤을 정상 계약으로 본다. 모든 필드와 분석 버튼은 DOM 순서대로 즉시 접근할 수 있어야 하지만 첫 화면 안에 분석 버튼이 보이는 것을 보장하지 않는다.

## 5. 세로 사양

기준 높이는 viewport가 아니라 헤더와 앱 chrome을 제외한 `workspace clientHeight`다. 해양 캔버스가 세로 스크롤을 소유하며, 고정 패널 높이로 분석 버튼을 화면 밖에 강제로 밀지 않는다. 다음 표의 패널 높이는 2열 레이아웃에 적용하고, 한 열은 앞 절의 개별 높이와 연속 스크롤 계약을 우선한다.

| 요소 | workspace 800px 이상 | workspace 720–799px | workspace 719px 이하 |
|---|---:|---:|---:|
| 상단 제목 영역 | 120 | 88 | 72 |
| 제목과 패널 사이 | 20 | 12 | 12 |
| 업로드·정보 패널 | 내용 기반, min 480 | 내용 기반, min 420 | 내용 기반, min 360 |
| 패널과 분석 버튼 사이 | 24 | 16 | 12 |
| 분석 버튼 | 72 | 64 | 60 |
| 버튼 아래 안전 여백 | 28 | 20 | 16 |

### 세로 정렬

- 업로드 패널과 회의 정보 패널의 상단과 하단을 일치시킨다.
- `분석 시작` 버튼은 회의 정보 패널 아래에 배치한다.
- 버튼과 회의 정보 패널의 오른쪽 끝선은 정확히 같다.
- 버튼은 업로드 영역 아래로 이동하지 않는다.
- 높이가 부족하면 제목 영역, 패널 내부 세로 여백, 장식 노출 순서로 줄인다.
- 조건부 이어하기·readiness 오류·파일 안내가 나타나면 작업 캔버스 전체가 스크롤한다. 고정 높이에 내용을 압축하거나 패널 내부 스크롤로 숨기지 않는다.
- workspace 719px 이하에서는 첫 화면 고정을 보장하지 않고, 분석 버튼까지 한 번의 연속 스크롤로 접근 가능하게 한다.

## 6. 요소별 고정 사양

### 사이드바

- 모든 지원 너비에서 기존 컴포넌트 폭 `272px`를 유지한다.
- 배경은 짙은 해양 청록의 불투명 표면이다.
- 바다 배경 이미지가 사이드바 아래로 비치지 않는다.
- 기존 탐색 순서와 기능을 유지한다.
- `새 기록`은 생성 동작이라는 기존 제품 규칙을 보존한다. 선택된 페이지처럼 과도한 테두리나 입체 카드로 만들지 않는다.

### 제목 영역

- 작업 레일의 왼쪽 시작선과 맞춘다.
- `새 회의록` 제목은 20–24px 범위다.
- 고래나 햇빛이 제목 뒤에 있더라도 텍스트 대비 `4.5:1` 이상을 확보한다.
- 시안에 표현된 날짜가 실제 제품에서 중복 정보라면 제목 아래 장식 정보로 강제 추가하지 않는다.

### 업로드 패널

- 너비는 표의 `Upload` 열을 따른다.
- 높이는 회의 정보 패널과 같다.
- 반경은 기존 디자인 시스템의 카드 반경을 사용한다.
- 밝은 바다 유리 hairline과 내부 수면 하이라이트를 사용한다.
- 업로드 아이콘, 안내, 파일 선택, 형식 배지는 중앙 세로축을 공유한다.
- 물결은 아이콘 중심에서 퍼지는 네 겹의 얇은 원이다.
- 물결 외곽이 패널 테두리와 접하지 않게 최소 `36px` 여백을 둔다.
- 물결은 CSS 또는 SVG로 만든다. 래스터 이미지 한 장으로 확대하지 않는다.

### 회의 정보 패널

- 너비는 표의 `Meeting` 열을 따른다.
- 업로드 패널과 같은 높이와 상단선을 사용한다.
- 배경 불투명도는 시각적으로 `94–97%`에 해당하는 밝은 바다 유리다.
- 입력 필드 주변은 거의 흰색으로 유지한다.
- 배경 생물, 산호, 물결 텍스처를 입력 필드 뒤에 배치하지 않는다.
- 상단에만 매우 약한 곡선형 수면 하이라이트를 허용한다.
- 필드 폭은 패널의 내부 여백을 제외하고 채우되, 패널 자체가 최대 `448px`를 넘지 않는다.

### 분석 시작 버튼

- 2열 기준 크기: `220–240 × 72px`.
- 한 열 기준 크기: `220–240 × 60px`.
- 2열과 한 열 모두 버튼의 오른쪽 끝만 회의 정보 패널과 정렬한다.
- 선택 이미지에서 버튼 높이가 더 크게 보이는 것은 생성 시안의 과장으로 보고, 실제 업무용 UI에서는 `72px`로 제한하는 승인된 구현 편차다.
- 실제 hit area와 포커스 외곽은 둥근 직사각형이다.
- 내부에 고래꼬리 아이콘과 `분석 시작` 문구를 둔다.
- 버튼 외곽을 고래나 꼬리 모양으로 만들지 않는다.
- 단색 파란색 대신 깊은 청록 반투명 유리, 밝은 청록 hairline, 제한된 내부 수면광을 사용한다.
- 별도 카드, footer, command bar 배경을 만들지 않는다.

## 7. 배경판과 장식 에셋 사양

선택된 합성 시안은 UI가 제거된 작업 영역 전용 배경판을 제작하기 위한 위치 참고다. 런타임에는 다음 단위로 구성한다.

| 에셋 | 기준점 | 넓은 화면 동작 | 좁은 화면 동작 |
|---|---|---|---|
| `ocean-workspace-wide.webp` | 캔버스 전체, 우측 상단 초점 | `cover`, UI 안전 영역을 보존 | compact 전환 전까지만 사용 |
| `ocean-workspace-compact.webp` | 캔버스 전체, 상단 수면광 초점 | 사용하지 않음 | 장식 밀도를 낮추고 고래·산호보다 입력 안전 영역 우선 |
| CSS 대비 오버레이 | 캔버스 전체 | 상태별 불투명도만 조절 | 같은 계약 유지 |
| 고래꼬리 버튼 장식 | 버튼 내부 | 고정 비율 `contain` | 버튼 안에서 축소 |

### 이미지 크기와 크롭 원칙

- 배경판은 `background-size: cover`와 고정 초점 위치를 사용하며 비균일 확대를 금지한다.
- 넓은 화면과 좁은 화면은 한 이미지를 억지로 자르지 않고 최대 두 개의 의도된 크롭을 사용한다.
- wide/compact 전환은 viewport가 아니라 사이드바를 제외한 작업 캔버스의 실제 inline size를 기준으로 한다.
- 앱의 실제 최소 창 `1100 × 720`에서는 작업 캔버스가 약 `828px`로 전환 경계에 걸리므로 별도 검증한다.
- 낮은 창에서는 고래·산호의 보존보다 제목, 입력, 오류, 분석 버튼의 안전 영역과 대비를 우선한다.
- 배경 이미지 로딩 실패 전부터 단색 해양 배경색을 표시한다.

### 배경판 safe zone

- wide 배경판의 고래와 강한 산호는 작업 레일 오른쪽 환경 여백에 둔다. 패널 뒤에 숨기는 것을 안전 배치로 간주하지 않는다.
- compact 배경판은 중앙과 왼쪽을 낮은 대비로 비우고, 고래·물고기·산호를 약화하거나 제거한다.
- 시작 화면은 제목과 CTA, 새 회의록은 업로드·회의 정보·분석 버튼, 분석 진행은 진행 패널을 각각 안전 영역으로 삼는다.
- CSS 대비 오버레이는 안전 영역을 보완하지만 원화의 잘못된 배치를 가리는 용도로 사용하지 않는다.

## 8. 반응형 우선순위

좁아질 때 다음 순서로 양보한다.

1. 작업 캔버스가 `832px` 미만이면 compact 배경판으로 전환한다.
2. 낮은 창에서는 CSS 오버레이를 강화하고 장식보다 UI 안전 영역을 우선한다.
3. 작업 레일의 좌우 inset을 줄인다.
4. 업로드와 회의 정보 패널을 표의 최소 폭까지 줄인다.
5. 캔버스가 `832px` 미만이면 한 열로 전환한다. 앱 최소 창 `1100px`에서는 경계값 반올림과 가로 overflow를 별도로 확인한다.

다음 요소는 먼저 줄이거나 숨기지 않는다.

- 회의 제목, 일시, 목적 입력
- 파일 선택 동작
- 분석 시작 버튼
- 오류, 필수 설정, 복구 안내
- 키보드 포커스 표시

## 9. 레이어와 클릭 규칙

```text
해양 캔버스: position: relative; isolation: isolate; overflow-x: clip; overflow-y: auto

z-index 0   base ocean gradient
z-index 1   WebP background plate
z-index 2   CSS contrast overlay
z-index 3   title and work panels
z-index 4   analysis button and interactive controls
z-index 5   focus rings, menus, dialogs, toasts
```

- 배경판과 장식 에셋은 `pointer-events: none`이다.
- 배경판과 장식 에셋은 접근성 트리에서 제외한다.
- focus ring은 환경 장면보다 위에 표시한다.
- 팝오버와 파일 선택 동작이 장면 레이어에 가려지지 않아야 한다.

## 10. 에셋 성능 예산

- UI가 포함된 합성 기준 PNG는 런타임 에셋으로 사용하지 않는다.
- wide/compact WebP 배경판 합계는 `1.2MB` 이하를 목표로 하고 `1.8MB`를 상한으로 한다.
- 버튼 장식 WebP는 `80KB` 이하를 목표로 하고 `140KB`를 상한으로 한다.
- source pixel size는 실제 최대 표시 크기의 2배를 넘지 않는다.
- 배경판은 레이아웃에 참여하지 않는 CSS background layer로 구현하고 `@container`에서 wide/compact URL을 전환한다. 배경색을 먼저 선언해 이미지 전환과 로딩 실패가 레이아웃 이동을 만들지 않게 한다.
- 고래꼬리처럼 실제 `<img>`로 배치하는 장식에는 고정 intrinsic `width`와 `height`를 선언한다.
- `backdrop-filter`는 업로드, 회의 정보, 분석 버튼의 세 표면에 중첩 적용하지 않는다. 반투명 색과 제한된 내부 하이라이트를 우선한다.
- 최초 진입 배경판은 지연 로딩하지 않는다. 버튼 장식은 비동기 디코딩할 수 있지만 실제 버튼과 문구가 먼저 표시되어야 한다.

## 11. 동작 상태

### 분석 시작 버튼

- 기본: 깊은 청록 유리와 흰 텍스트.
- hover: 내부 물결이 4–6px 이동하고 테두리가 조금 밝아진다.
- focus-visible: 기존 `--focus-ring-color` 기반 2px 외곽선과 간격을 사용한다.
- pressed: 내부 하이라이트가 약해지고 `translateY(1px)` 이내로 제한한다.
- disabled: 텍스트 대비를 유지하면서 채도, 테두리, 내부광을 함께 낮춘다.
- loading: 고래꼬리 위치에 작은 스피너, 문구는 실제 제품의 현재 진행 문구를 사용한다.
- 버튼은 `aria-busy`와 실제 disabled 계약을 유지하고, disabled에서는 고래꼬리 이미지와 내부광도 함께 감쇠한다.
- `prefers-reduced-motion: reduce`에서는 물결과 햇빛 이동을 정지한다.

### 업로드 물결

- 기본 상태에서는 정적인 네 겹 물결 또는 8초 이상의 매우 느린 호흡만 허용한다.
- drag-over에서는 한 번 확산하고 테두리를 밝게 한다.
- 지속적으로 빠르게 반복되는 파동은 사용하지 않는다.

## 12. 기능 계약

선택 시안에서는 하단 `참석자 구분` UI가 없다. 설정 화면을 이 옵션의 단일 소유자로 사용하며 기존 저장값과 `diarization_during_analysis` payload 계약을 유지한다.

- 설정을 닫은 뒤 MeetingWriter가 이전 값을 보내지 않도록 공유 설정 상태를 갱신하거나 분석 시작 직전에 최신 설정을 다시 읽는다.
- 저장값을 삭제하거나 고정된 true/false로 덮어쓰지 않는다.
- 회귀 테스트는 `설정에서 변경 → 닫기 → 분석 시작 → 전송 payload 확인`을 포함한다.

## 13. 접근성·상태 안정성

- 일반 텍스트는 `4.5:1`, 큰 텍스트와 아이콘은 `3:1`, 입력·버튼 경계는 주변 배경과 `3:1`을 목표로 한다.
- placeholder와 글자 수 counter도 바다 유리 위에서 읽을 수 있어야 한다.
- 파일 선택은 클릭과 키보드 모두 가능해야 하며 drag-over만 유일한 입력 경로가 되어서는 안 된다.
- 오류, 선택된 파일, 이어하기, readiness 안내는 예약된 흐름 안에서 나타나고 분석 버튼의 가로 정렬을 바꾸지 않는다.
- `forced-colors`에서는 배경 장면과 반투명 효과를 제거하고 시스템 색상 기반 경계와 텍스트를 사용한다.
- 투명도 감소 환경에서는 밝은 불투명 작업 표면과 단색 해양 배경으로 대체한다.
- `backdrop-filter` 미지원과 배경판 로딩 실패에서도 불투명 기본색과 1px 경계만으로 같은 대비와 조작 가능성을 유지한다.

## 14. 구현 검증 게이트

각 너비에서 실제 화면을 캡처하고 아래를 확인한다.

### 1024px

- 한 열 레이아웃이 가로 스크롤 없이 보인다.
- 회의 정보 입력이 지나치게 좁아지지 않는다.
- 고래와 산호가 필드를 침범하지 않는다.
- 한 열 계약에 따라 workspace 높이와 무관하게 캔버스 스크롤로 분석 버튼에 바로 접근할 수 있고, 버튼 오른쪽 끝은 회의 정보 패널의 오른쪽 끝과 맞는다.

### 앱 최소 창 1100×720

- 272px 사이드바를 제외한 작업 캔버스가 약 828px일 때 compact 전환과 1열 전환의 경계가 일치한다.
- 경계값 반올림으로 두 열이 잘리거나 가로 스크롤이 생기지 않는다.
- 고래와 산호보다 입력·오류·분석 버튼의 안전 영역을 우선한다.

### 1280px

- 작업 패널의 비율이 `488 / 368`에 가깝다.
- 환경 생물이 오른쪽 주변부에만 있다.
- 바다 여백과 작업 UI가 균형을 이룬다.

### 1440px

- 선택 이미지의 축소된 2열 구성을 유지한다. 최종 시각 기준과 가장 가까운 fidelity baseline은 1600px이다.
- 작업 레일은 약 `976px`, 업로드 `536px`, 회의 정보 `416px`다.
- 버튼 우측선과 회의 정보 패널 우측선이 일치한다.

### 1600px 이상 fidelity baseline

- 선택 이미지와 가장 가까운 비율을 사용한다.
- 패널 크기가 더 커지지 않는다.
- 배경 에셋이 확대되거나 흐려지지 않는다.
- 늘어난 공간에는 바다의 빈 공간이 자연스럽게 보인다.
- 고래와 산호의 anchor가 유지된다.

### 높이별 확인

- workspace `720px`, `800px`, `900px`에서 idle, 파일 선택, 이어하기, readiness 오류 상태를 각각 확인한다.
- 분석 버튼 접근 가능성, 캔버스 스크롤 소유권, 패널 내부 overflow 부재를 확인한다.

## 15. 완료 조건

- 선택 시안의 구조와 정렬이 1024·1280·1440px에서 유지된다.
- 1600px 이후 패널 최대 폭이 고정된다.
- 배경은 UI가 제거된 wide/compact WebP 배경판과 CSS fallback으로 구성되며 찌그러짐이나 무제한 확대가 없다.
- 하단 별도 영역이 없다.
- 분석 버튼의 오른쪽 정렬과 상태 디자인이 일관된다.
- 기능과 저장 데이터는 별도 승인 없이 변경되지 않는다.
- 키보드, 포커스, reduced motion, 가로 overflow 검증을 통과한다.
