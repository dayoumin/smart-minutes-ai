# LMO 회의록 디자인 기준

- 2026-10-23 승인 배치 시안의 실제 반영(이전 I안 배치·수동 메뉴 접기 규칙 대체): 1200px 이상은208px 라벨 메뉴를 고정하고 접기 기호를 없앤다. 그보다 좁은 데스크톱 창은64px 상단에 로고·`메뉴`·설정을 두고, 메뉴는240px 겹친 목록으로 연다. `메뉴 닫기`·메뉴 밖 클릭·Esc·Tab 순환과 설정/창 크기 변경 뒤 초점 복귀를 유지한다. 예전 `sidebarCollapsed` 선택은 읽거나 쓰지 않는다.
- 첫 작성 화면은 제목과 본문을 같은1120px 콘텐츠 폭에 맞춘다. 정보 칸248px(입력224px+오른쪽24px 여백)과 오른쪽 작업 칸을 둔다. 작업 칸832px 이상에서는 업로드·분석을 넓게, 로컬 처리 장점은 우측288px 그림 영역에 두며 간격은32px이다. 반반 분할은 하지 않는다. 그보다 좁으면 업로드·분석 다음에 안내를 배치한다. 정보와 작업의2단 기준800px은 유지한다. 저장된 회의록은 왼쪽 목록에서 열고 작업면 아래에 중복 목록이나 빈 목록 안내를 두지 않는다(2026-10-27 사용자 결정).
- 로컬 처리 장점은 첫 화면에 항상 표시한다: `이 PC에서 분석·요약합니다` 제목(16px·600), 노트북 화면 안의 영상·음성→이 PC에서 처리→대화록·회의 요약 그림, `외부 AI 전송 없음`을 함께 둔다. 2026-10-23 이미지 시안 승인 후 제목 아래 부연설명과 그림 안의 반복 제목은 삭제했다. 후속 요청으로 `처리·보관 방식 자세히` 상시 링크도 제거했다. 처리·인터넷·보관·삭제의 전체 설명은 운영 웹의 브라우저별 첫 접속 안내에만 두며, 닫은 사실을 기억해 재방문 때 반복하지 않는다. 넓은 창에서는 업로드·분석 영역과 안내 영역의 상단·하단을 맞춘다. 그림은 기존 색과 아이콘을 쓰며 같은 폭의 세 칸으로 아이콘 중심과 좌우 여백을 맞춘다. 노트북은 화면 테두리·카메라·키보드·트랙패드·앞쪽 받침으로 인식되게 하며 화면 비율을 미리 정해 로딩으로 위치가 바뀌지 않게 한다.
- 제목·일시·회의 목적의 필수 여부는 입력 전에 작은 `필수` 표시로 알리며 접근 가능한 입력 이름은 유지한다. 파일을 고르기 전에도 지원 형식 옆에 최대 분석 시간(현재2시간)을 표시하고 실제 제한 상수를 공유한다.
- 2026-10-23 노트북 위치 고정: 넓은 창은 제목 아래22px에 그림을 두어 상태 영역 높이와 무관하게 유지한다. 링크 제거 전 승인한1440px 화면의 그림 상단169px을 보존한다. 좁은 창은 제목 내용 폭·24px 간격·224px 그림의 고정된 두 칸을 왼쪽부터 배치해 창 너비에 따라 그림이 오른쪽으로 흩어지지 않게 한다(860↔1024px 위치 동일). 이 묶음이 들어가지 않는448px 이하 작업 폭에서는 한 열로 배치한다. 연결 무응답은 단순 대기 대신 `연결 프로그램 실행 후 ‘다시 확인’을 눌러 주세요.`로 행동을 안내하고, 도움말에서 Windows 시작 메뉴 실행 위치와 이미 실행 중일 때의 재실행을 설명한다.
- 레이아웃 안정성 검증: 분석 시작뿐 아니라 제목·업로드·로컬 처리 안내의 위치와 크기를 함께 확인한다. `?`의 부가 도움말은 본문을 미는 인라인 행이 아니라 겹쳐 여는 비모달 팝업이며, 바깥 클릭·Esc로 닫는다. 다른 모달 안의 Esc와 초점 복귀를 가로채지 않는다. 오류의 핵심 원인·필수 복구 안내는 계속 본문에 남긴다. 긴 활성 콘텐츠를 자르거나 높이를 억지로 고정하는 규칙은 아니다.

- 2026-10-21 요약 확인 안내: `기록 정리`의 전체 요약·주제별·참석자별 탭에 `AI가 정리한 내용에는 누락이나 잘못된 해석이 있을 수 있습니다. 중요한 내용은 대화록과 대조해 주세요.`를 항상 표시한다. 요약 생성 전·재열기에도 같은 공통 위치를 유지하고, 14px 본문과 `대화록 확인` 버튼을 사용한다. 버튼은 대화록 탭을 열고 해당 탭으로 키보드 초점을 옮긴다. 이 안내는 결과를 해석하는 데 필요한 지속 안내이며 팝업·닫기·동의 절차를 추가하지 않는다. 상태/오류 안내와 별도로 둬서 생성 상태가 바뀌어도 사라지지 않는다.

- 2026-10-21 웹 엔진 업데이트 안내: 접속할 때 같은 출처의 `/downloads/engine-beta.json`과 공개 probe의 설치 버전을 비교한다. 호환되는 구버전은 작성 화면의 기존 상태 줄에 안내색 `새 버전이 있습니다`, 버전 비교(`0.1.9 → 0.1.10`), `다시 확인`·`최신 설치 파일 받기`를 보이며 분석은 허용한다. 같은 기본 버전 내 시험판 갱신이면 전체 버전을 표시하고, 다른 기본 버전 간 비교는 짧게 쓰되 `?`에서 전체 버전·다운로드 후 설치 실행·분석 완료 후 설치를 안내한다. 모델·입력 등 현재 막힘은 선택 업데이트보다 우선한다. 미인증 구버전에도 설치 버튼을 제공하고, 브라우저 차단·연결 진행·필수 업데이트는 기존 복구 안내를 우선한다. 설치 후 포커스 복귀·10초 확인으로 안내를 없애며 상태 줄과 `분석 시작` 위치를 유지한다. 최신 정보 조회는 5초 이내에 끝내고 실패해도 정상 사용을 막지 않는다. 최신/더 새 버전에는 안내·팝업을 표시하지 않는다.

- 2026-10-20 연결 결정: LMO 회의록 연결 설치 후 웹에서 자동 연결한다. 숫자 코드·별도 Windows 승인 창·연결 준비 시간 제한을 사용자 흐름에 두지 않는다. 브라우저의 `기기에 있는 앱` 권한은 브라우저가 요구할 때만 안내한다. 새로고침·엔진 재실행은 자동 복원하고, 명시적 연결 해제는 현재 방문의 자동 재연결보다 우선한다.
- 2026-10-20 설치 프로그램 이름 결정: Windows 설치 창·앱 목록·시작 메뉴의 표시 이름은 브랜드 없이 `음성 분석`이다(`로컬 엔진` 대신, 브랜드는 바뀔 수 있어 이름에 넣지 않는다). 시작 메뉴의 연결 바로가기는 웹 문구와 같은 `<브랜드> 연결`(`LOCAL_ENGINE_NAME`, 현재 `LMO 회의록 연결`)이며, 설치 빌드가 `configs/brand.json`의 이름을 `BRAND_NAME`으로 넘긴다. 웹이 설치 프로그램을 `<브랜드> 연결`로 부르는 현재 문구를 `음성 분석`으로 옮길지는 따로 정하고, 옮기면 아래 "다시 설치할 대상은 웹은 `LMO 회의록 연결`", "웹 `LMO 회의록 연결 확인 중`", "엔진 이름은 `LMO 회의록 연결` 하나만 쓴다"와 바로가기를 함께 고친다.

AI 보조 디자인에서 시안·스킬·구현·검증을 적용하는 순서는 `docs/ai-assisted-ui-workflow.md`를 따른다. 2026-10-17 이전 계획과 시안(프로덕션 시안 여섯 장, 해양·고래 테마, Compact Monochrome 후보)은 `docs/archive/design-2026-06-to-10/`에 보관했고 구현 근거로 쓰지 않는다.

## 현재 방향: A「조용한 문서」 (2026-10-17 채택)

- 사용자가 Figma 탐색안 세 개(A 조용한 문서, B 분할 작업대, C 바다 편집본) 중 A를 선택했다. 시안: https://www.figma.com/design/A8ny8v22BU9Wj6fvHaOIxG (A1 새 회의록 `2-23`, A2 회의 상세 `2-139`, 새 회의록 동작 줄 v2 `15-438`). Mobbin 참고는 Otter·Amie·Fireflies·Grain의 문서형 화면이다. Figma에는 Pretendard가 없어 Noto Sans KR로 그렸으며 구현은 Pretendard를 유지한다.
- 구현 단계: ① 앱 셸·토큰·사이드바(완료, `1807dc6`) → ② 회의 상세(가운데 문서 열, 속성 행, 밑줄 탭, 문서형 기록 정리, 완료) → ③ 새 회의록(해양 장면과 별도 시작 화면을 걷고 업로드·회의 정보·최근 목록을 한 화면에, 완료) → ④ 분석 진행·설정·기록 찾기 정렬(완료). 각 단계는 검증·agent 검토·사용자 확인 후 다음으로 넘어간다.
- 해양 장면(배경 사진, 유리 카드, 고래 꼬리 버튼)과 별도 시작 화면은 ③에서 코드·이미지·테스트까지 지웠다. 되살리지 않는다. ④에서 옛 파랑·해양·Refero 토큰, 유리 카드, 화면 뒤 등고선 장식도 지웠다.
- 시안에만 있는 요소는 구현하지 않는다: 사이드바 `검색 Ctrl K`(기록 찾기 숨김 결정과 충돌), 할 일 체크박스·담당자·시점 링크(저장 데이터 없음). 데이터가 생기면 다시 판단한다. 이 원칙은 모든 시안에 적용한다. 실제 데이터와 동작이 없는 메뉴, 상태, 진행 단계, 통계, 내보내기 형식을 화면에 먼저 노출하지 않는다.

## 회의 상세·분석 진행 2단 배치 (2026-10-22 채택, 소스 구현)

- 2026-10-23 첫 화면 강조·상태 배치 후속: 업로드 영역은 옅은 브랜드 배경과 채움색 `파일 선택` 버튼으로 첫 행동을 강조하고, 처리·보관 안내는 흰 배경으로 낮춘다. 업로드 열 안에서는 준비/오류/필수 입력 상태가 열 전체 폭을 쓰고 복구·분석 시작 버튼은 그 아래 오른쪽에 둔다. 정상 준비 상태도 같은 두 행을 사용한다. 상태의 최소 높이44px(20px 제목·4px 간격·20px 설명)과 버튼 위12px 간격을 유지한다. 제목·설명 시작선을 맞추고 버튼은 같은 높이로 정렬하며 사이 간격8px을 둔다. 도움말은 겹친 팝업으로 열어 버튼 위치를 밀지 않는다. 이 결정은 아래의 이전 정상 상태를 시작 버튼 왼쪽16px에 두던 기준과40px 최소 높이를 대체한다. 긴 안내는 자르지 않고 자연스럽게 늘어나도록 한다.

- 2026-10-23 메뉴 사용성 후속: 사용자가 접을 때와 같은 맨 위 위치에서 다시 펼치기를 기대하므로, 아이콘 줄은 `메뉴 펼치기` → 로고 → `새 회의록` → `회의록 목록` 순서로 조정한다. 아래의 이전 로고 우선 순서보다 이 결정을 우선한다. 접기/펼치기는 같은 상단 높이에 두고, 로고의 첫 화면 이동 역할은 유지한다. 주요 메뉴는 14px, 구분 제목과 폴더 없는 목록의 빈 안내는 13px으로 표시한다. 날짜 등 보조 정보까지 일괄 확대하지 않는다.

- 배경: A2 한 열 상세는 제목·속성 행이 약 450px를 차지해 넓은 창에서도 탭 본문이 늦게 시작하고 좌우가 비었다. 사용자가 고정된 회의 정보를 옆 칸으로 빼고 `기록 정리`·`대화록`·`보고서` 탭이 화면 높이를 쓰게 하자고 정했다. 참고는 Apollo(왼쪽 재생기, 오른쪽 요약·대화록 탭), Twenty(왼쪽 필드, 오른쪽 탭), Fireflies다. 2026-10-17 탐색안 B(정리와 대화록을 나란히 두는 3단)와 다르다. 정리와 대화록은 계속 탭으로 바꿔 본다.
- 시안(같은 Figma 파일): D2 회의 상세 `44:1691`, D3 분석 진행 `45:1706`, D4 좁은 창 1024×768 `46:1736`(아이콘 메뉴), D5 좁은 창 메뉴 펼침 `47:1758`. 시안 머리글은 실제 결정대로 제목과 기존 동작(음성 저장·수정)만 그렸다. 제목을 정보 칸 맨 위에 둔 D1 `43:1676`은 사용자가 입력하는 긴 제목이 280px에서 단어 중간에 끊겨 채택하지 않았다.
- 메뉴 승인안(2026-10-22): [E · 메뉴 펼침·아이콘·겹쳐 열기](https://www.figma.com/design/A8ny8v22BU9Wj6fvHaOIxG?node-id=49-1740). E1 `49:1741`, E2 `49:1930`, E3 `49:2108`은 기존 원본을 보존하고 네이티브 레이어·구성요소 인스턴스를 재사용한 편집 가능한 화면이다. 이미지 시안의 메뉴 동작을 기존 제품 스타일로 옮겼다. 원본의 Noto Sans KR 글꼴은 유지했고 실제 웹은 기존 Pretendard Variable을 유지한다. 주변 요약 내용과 탭 표현은 기존 Figma 참고 화면이며 전체 소스 동기화를 뜻하지 않는다.
- 머리글(상세 영역 전체 폭, 아래 경계선 한 줄): 지금처럼 회의 제목(30px)과 오른쪽 기존 동작(음성 저장, 수정, 수정 중 저장·취소)을 한 줄에 둔다. 시안의 폴더 경로와 머리글 `내보내기`·더보기는 넣지 않는다. 상세는 폴더 이름을 받지 않고, 내보내기는 각 탭 command bar의 기존 다운로드 동작이다. 제목을 감싸던 테두리 상자는 없앤다. 분석 진행 중에도 같은 머리글을 쓰고(동작은 지금처럼 `inert`), 분석이 끝나 상세로 바뀔 때 제목·정보 칸·탭이 움직이지 않는다.

## 토큰과 표면

- UI 글꼴은 앱에 포함한 Pretendard Variable v1.3.9를 쓴다(`public/fonts/pretendard/`, SIL OFL 원문 동봉). [공식 배포본](https://github.com/orioncactus/pretendard/tree/v1.3.9/packages/pretendard/dist/web/variable/woff2)을 그대로 보관하고 외부 폰트 서버나 PC 설치 여부에 의존하지 않는다. `--font-ui`와 Tailwind `font-sans`를 같은 글꼴로 연결한다.
- 목록·상하위 메뉴는 공통 `--type-ui-*` 기준(14px/20px), 구역명·날짜는 `--type-meta-*` 기준(12px/16px)으로 표시한다. 목록의 기본 굵기는 400, 선택 항목은 500이며 브랜드는 15px/700을 유지한다. 회의록 제목·날짜는 `ui-item-text`/`ui-meta-text`를 쓰고, 메뉴와 사이드바 공통 클래스도 같은 기준을 따른다. 하위 메뉴를 깊이에 따라 작게 만들지 않는다.
- 페이지와 작업면은 흰색이다. 중립색은 따뜻한 회색(`--color-neutral-50` #FAFAF8 ~ `--color-neutral-900` #1C1C1B)을 쓴다.
- 주 강조색은 청록 `--barorok-teal`(#0F7B83)이며 `--brand-primary`로 쓴다. 진한 색 #0B6168은 hover, 옅은 색 #E5F2F2는 선택·강조 배경이다. 주 버튼, 선택 탭 밑줄, 링크, 포커스 링이 이 색을 쓴다.
- 상태색(정보·경고·오류·성공·중립)은 semantic status token을 그대로 쓴다. 청록을 상태 의미로 쓰지 않는다. 성공은 초록(`--status-success-*`, 글자 #166534)이며 브랜드 청록과 헷갈리는 시안색을 쓰지 않는다.
- 표면은 테두리 한 줄로 구분하고 그림자를 깔지 않는다. 그림자는 모달·팝오버·메뉴처럼 떠 있는 표면(`--shadow-overlay`)과 입력·버튼의 얕은 `--shadow-control`에만 쓴다. 상자 안에 상자를 겹치지 않는다. 오버레이 배경은 따뜻한 회색 `--bg-overlay`다.
- 해양·수산 정체성은 청록 강조색과 파형 브랜드 마크 정도로만 드러낸다. 해양 사진이나 생성 이미지를 대화록·기록 정리·보고서 본문 뒤에 두지 않는다.
- 대비: 본문·작은 글자는 4.5:1 이상, 아이콘·포커스 링은 3:1 이상을 지킨다. `--text-subtle`(#9C9C97)은 글자에 쓰지 않고 글자 옆 아이콘에만 쓴다. 포커스 링은 `--brand-primary`를 그대로 쓴다.
- 카드 반경은 작게 유지하고, 정보 밀도는 업무 도구에 맞게 차분하게 유지한다. 반복 작업 표면은 `--radius-card`, 버튼과 입력은 `--radius-btn`, 모달은 `--radius-dialog`를 쓴다. 화면 파일에서 임의 반경을 새로 만들지 않는다.

## 앱 셸과 사이드바

- 앱은 바깥 프레임·여백·라운드 없이 창 전체를 채운다. 앱 위에 별도 상단 헤더를 두지 않는다. 웹에서는 브라우저가 창 제목줄을 이미 제공하므로 창 제어 줄을 재현하지 않는다.
- 웹의 새 회의록 제목줄 오른쪽에는 `데스크톱 앱 받기`를 둔다. 데스크톱 앱 안에는 표시하지 않는다. 별도 상단 바를 추가하지 않고 기존 제목줄을 사용한다. 누르면 신규 설치 ZIP의 압축 풀기·실행·첫 모델 준비와 웹 기록이 자동 이전되지 않는다는 안내를 먼저 보여주며, `Windows용 ZIP 받기`를 명시적으로 눌러야 파일을 요청한다. 미공개·조회 실패는 안내창 안에서 구분하고 재확인을 제공한다.
- 사이드바는 240px 고정 폭, 배경 `--barorok-sidebar`(#F7F7F5), 오른쪽 경계 한 줄이다. 위에서부터 브랜드(26px 청록 사각형 + `LMO 회의록`, 누르면 새 회의록 화면), `새 회의록`, `폴더` 구역(구역 이름 옆 `+`가 폴더 만들기), `회의록` 구역, 맨 아래 `설정` 순서다. `분석 중` 카드, `이어서 할 분석` 묶음, 새 회의록 잠금 안내는 `설정` 바로 위 고정 영역에 둔다. 폴더·회의록 스크롤 목록 안에 끼워 넣지 않아서 분석이 시작되거나 이어서 할 분석이 생겨도 목록 위치가 바뀌지 않는다. 펼친 미완료 목록은 창 높이의 40%까지만 커지고 그 안에서 스크롤한다.
- 사이드바는 `새 회의록`, 폴더, 회의록 목록, 분석 중·이어하기, 설정을 소유한다. 오른쪽 작업면은 새 회의록, 분석 진행, 선택한 회의록 상세 중 하나만 보여준다. 저장된 기록의 목록·폴더·관리 메뉴는 사이드바에만 두고, 새 회의록 아래에 최근 회의록을 반복하지 않는다(2026-10-27).
- 사이드바에는 목적을 반복하는 `회의 기록` 제목, 모든 목록을 다시 뜻하는 `전체 기록`, 시스템 분류처럼 보이는 `미분류` 항목을 두지 않는다. 사용자가 실제로 만든 폴더만 탐색 항목으로 보인다.
- 폴더를 누르면 바로 아래에 해당 회의록을 펼치고, 다시 누르면 접는다. 여러 폴더를 동시에 열 수 있으며 폴더마다 처음 5개를 표시하고 `더 보기`로 5개씩 추가한다. 폴더 없는 회의록은 아래 `회의록` 구역에 모두 유지한다. 목록이 길면 폴더·회의록 공통 영역만 스크롤하며 브랜드·새 회의록·설정과 상태 영역은 고정한다.
- 분석이 진행되는 동안 `새 회의록`은 비활성화(반투명, hover 배경 없음)하고 이유를 title과 숨김 설명(`aria-describedby`)으로 알린다. 사이드바 포커스가 갈 곳을 잃으면 비활성 버튼 대신 `분석 중` 카드, 그다음 로고로 보낸다. 진행 화면으로 돌아가는 입구는 `분석 중` 카드(와 로고)다. 버튼 이름을 `진행 중인 분석 보기`로 바꾸지 않는다.
- `새 회의록`은 현재 위치가 아니라 생성 동작이므로 테두리·그림자·강조 글자색을 두지 않는다. 기본 글자색에 hover 때만 옅은 배경을 준다.
- 회의록 행은 제목(14px) 오른쪽에 `오늘`, `2일`, `1주`, `2개월`처럼 경과 시간(12px)을 둔다. 원래 일시는 title로 남긴다. 참석자 구분 상태가 있으면 상태 글자가 자기 폭을 차지하고(최대 104px, 넘치면 말줄임), 제목과 겹치지 않는다.
- 회의록·폴더 관리용 세로점 메뉴는 해당 행의 hover·키보드 focus 또는 메뉴가 열린 동안에만 보인다. hover·focus 중에는 경과 시간 자리에 메뉴를 보여 준다.
- `폴더 만들기`는 생성 동작만 제공한다. 폴더 행 메뉴는 `상단 고정`, `위로 이동`, `아래로 이동`, `이름 변경`, `삭제`를, 회의록 행 메뉴는 `상단 고정`을 제공한다. 고정된 항목은 각 목록 안에서 먼저 보이고, 폴더 수동 이동은 같은 고정 그룹 안에서만 한다. 마우스는 끌어서, 키보드는 메뉴의 위·아래 이동으로 순서를 바꾼다.
- 폴더를 만들어도 현재 보던 회의록 목록과 폴더 선택을 유지한다. 폴더를 선택해서 보는 동안에만 `회의록` 구역 옆에 `전체 보기`를 표시하고, 실행 후 첫 회의록으로 키보드 포커스를 옮긴다. 기존 회의록의 폴더는 행 메뉴의 `폴더 이동 ›`를 열면 옆에 나타나는 하위 메뉴에서 선택·변경한다. 폴더에 배정된 회의록에만 `폴더에서 빼기`를 제공하고, `폴더 없음` 항목은 표시하지 않는다. 이동할 폴더가 없고 현재 배정도 없으면 `폴더 이동`을 비활성화한다. 마우스를 올리거나 클릭해 열고, 키보드는 오른쪽 화살표로 진입·위아래 화살표로 선택·Enter로 이동·왼쪽 화살표/Escape로 복귀한다. 화면 끝에서는 하위 메뉴를 반대편에 표시하고 긴 목록은 내부에서 스크롤한다.
- 폴더와 회의록 목록은 하나의 세로 스크롤 영역을 공유한다. `새 회의록`과 하단 설정은 고정하고, 폴더가 많거나 창이 낮아도 마지막 폴더와 메뉴에 닿을 수 있어야 한다. 폴더 메뉴는 화면 안에 배치해 스크롤 경계에서 잘리지 않게 한다.
- `기록 찾기`는 회의·결정·할 일을 날짜순으로 찾는 별도 작업면이다. 2026-10-14 결정으로 사이드바 진입점은 숨겼다. 작업면 코드와 개발용 `?view=archive` 진입은 유지하고, 필요해지면 `App`에서 `Layout`에 `onOpenArchive`를 다시 넘겨 되살린다.

## 제품 범위

- 사용자 표시명은 `LMO 회의록`이다. `개인용 로컬 회의록`은 설명 문구로 쓰되 사이드바에는 표시하지 않는다. 내부 패키지명과 개발 경로는 유지한다.
- 브랜드 이름은 `configs/brand.json` 한 곳에만 쓴다. 화면 문구는 `desktop-app/src/brand.ts`의 `BRAND_NAME`·`LOCAL_ENGINE_NAME`을, 백엔드 문구는 `backend/brand.py`를 쓰고 이름 뒤 조사는 `withJosa`/`with_josa`로 붙인다. 데스크톱 앱 이름(`desktop-app/src-tauri/tauri.conf.json`의 `productName`·창 제목)은 JSON이라 값을 따로 두며 `backend/test_brand.py`가 같은지 확인한다. 이 문서에 적힌 이름은 현재 값 기준 예시다.
- 데스크톱과 웹은 같은 React UI와 디자인 토큰을 공유한다. 실행 환경 차이는 엔진·저장·연결 계층에서 처리하고 화면을 복제하지 않는다.
- 첫 제품은 HTTPS 웹 앱이 사용자가 내려받은 Windows 로컬 엔진에 연결하는 형태다. 엔진 받기, 연결·권한 복구, 모델 준비와 로컬 저장 상태를 사용자 동작 기준으로 설명하고, 음성·영상과 대화록이 원격 서버로 전송되는 것처럼 보이는 문구를 쓰지 않는다.
- Tauri 데스크톱은 같은 화면과 로컬 실행 계약을 재사용하는 후속 경로다. 웹 우선이라는 이유로 모바일·PWA·원격 SaaS 기능을 범위에 넣지 않는다.
- 기록 찾기 결과는 HWPX 보도자료·결과보고서 같은 후속 문서의 입력 후보가 될 수 있지만, 문서 편집기와 템플릿 UI는 기록 찾기 작업면에 섞지 않는다.

## 원칙

- 첫 화면 작업면은 회의록 작성에 집중하고, 저장된 기록은 왼쪽 목록에서 확인한다.
- 사용자 화면에는 모델명, 파이프라인, 서버 같은 내부 용어를 최소화한다.
- 반복 UI는 `index.css`의 공통 클래스를 우선 사용한다.
- 첫 화면의 제목 위에 화면 목적을 반복하는 보조 eyebrow를 붙이지 않는다.
- 섹션 제목 앞에 의미 없는 숫자 원형, 장식 점, 단계 마커를 넣지 않는다. 실제 순서 진행이나 상태를 전달할 때만 단계 표시를 쓴다.
- 기본값 저장, 자동 적용처럼 현재 조작에서 이미 암시되는 내용은 고정 보조 텍스트로 반복하지 않는다. 필요하면 title/tooltip에만 둔다.
- 상단 메타 정보, 탭, command bar, 본문은 같은 작업 흐름 안의 표면처럼 보여야 한다.
- 탭별 주요 실행 버튼은 관련 선택값과 함께 command bar에 두고, 위치와 높이를 일관되게 유지한다. command bar에서는 현재 탭의 핵심 동작 하나만 primary로 강조하고, 복사·파일 저장·이름 변경 같은 보조 동작은 outline 또는 ghost로 구분한다.
- 회의 선택, 탭 전환, 생성 진행 중에는 skeleton 또는 고정 높이 상태 UI로 레이아웃 흔들림을 줄인다. skeleton은 최초 진입이나 캐시에 없는 회의로 이동할 때만 작업면을 대체한다. 같은 회의의 background refresh는 현재 내용, 포커스, 편집 초안을 유지하고 실패 시 마지막 정상 상태를 보존한다.

## 콘텐츠 레일

- 본문은 작업 종류별 최대 폭을 쓴다. 데이터 표처럼 폭 자체가 정보량인 화면만 전체 작업 폭을 쓴다.
- 반응형 열 전환은 가능하면 전체 창 너비가 아니라 사이드바를 제외한 실제 콘텐츠 폭을 기준으로 한다.
- 2026-10-22: 아래 회의 상세의 문서 열·속성 행 배치·처리 상태 3열·첫 화면 기준은 「회의 상세·분석 진행 2단 배치」 구현 전까지의 현재 동작이다. 값과 문구 규칙은 2단 배치에서도 유지한다.
- 회의 상세(② A2): 카드 테두리·그림자 없이 가운데 880px(55rem) 문서 열에 놓는다. 대화록이 주 콘텐츠라 시안의 760px보다 넓혔고, 새 회의록·분석·기록 찾기와 같은 열을 써서 화면을 오갈 때 열이 옆으로 움직이지 않는다. 일시는 저장 문자열 대신 `2026년 10월 17일 (토) 오후 4:58`처럼 보여 준다.
- 제목(30px) 아래는 속성 행이다: 왼쪽 120px에 아이콘+라벨, 오른쪽에 값. 순서는 일시, 회의 목적(최대 두 줄, 넘치면 title), 참석자, 음성, 원본 파일(한 줄 말줄임), 처리 상태(테두리 없는 상태 칩과 참석자 구분 실행·중지)다. 참석자·음성 행은 분석 준비부터 결과 재열기까지 자리를 유지한다(2026-10-21). 참석자 값이 없으면 진행 중에는 `분석 후 확인할 수 있습니다.`, 결과에는 `참석자 정보 없음`이다. 참석자 칩은 구분이 적용됐거나 화자가 둘 이상일 때만 보이고, 8명을 넘으면 `외 N명`으로 줄인다. 값은 한 줄 고정 높이에 두고 넘치는 이름은 자르며 전체 이름을 title에 남긴다. 음성은 진행 중 안내·재생기·오류·`음성 없음`이 같은 높이를 쓴다. 완전한 결과 파일 목록(`json` 포함)에 `audio`가 없으면 조회하지 않고 `음성 없음`을 표시한다. 그 밖에 값이 없는 속성 행은 숨긴다.
- 첫 화면 기준(2026-10-17 변경): 예전의 `1280×720에서 첫 대화가 화면 절반 위` 기준은 속성 행 때문에 지키지 않는다. 대신 제목·속성은 문서처럼 스크롤되어 지나가고, 1280×720에서 첫 대화가 첫 화면 안에 보여야 한다(측정: 음성 행 없음 406px, 음성 행 있음 452px).
- 처리 상태에서 끝난 단계는 `완료` 글자 대신 초록 체크 아이콘(`status-done`, 보조기술에는 "완료")으로 보여 준다. 대기·진행 중·실패처럼 사용자가 확인해야 하는 상태는 글자 배지로 둔다.

- 첫 연결: Chrome `기기에 있는 앱` 권한이 정해지기 전에는 자동 확인이 요청을 보내지 않는다(커밋 `61858a52`). 그래서 첫 방문은 `LMO 회의록 연결이 필요합니다`와 `설치 파일`·`연결 확인`이고, 자동으로 연결된다고 말하지 않는다. 권한이 미정이면 확인 중·연결 실패 보조문에 `Chrome이 ‘기기에 있는 앱’을 물으면 ‘허용’을 눌러 주세요.`를 둔다. 연결 실패에서도 `설치 파일`을 도움말에 숨기지 않는다.

- `?` 도움말: 첫 버튼으로 풀리지 않을 수 있는 경고 상태에만 둔다. 24×24이고 20px 제목 줄 밖으로 넘치게 그려 줄 높이를 늘리지 않는다. `aria-expanded`·`aria-controls`를 쓰고, 펼친 내용은 `?` 바로 뒤 순서에 라이브 영역 밖으로 둔다. 데스크톱은 `?` 대신 `문제 해결` 버튼이다. `?`가 붙는 준비 상태(`분석 준비 상태를 확인하지 못했습니다`, `분석을 시작할 수 없습니다`)에서는 `문제 해결`을 고치는 버튼 `다시 확인`의 왼쪽에 둔다. 이 버튼은 `?` 자리라 "그 밖에서는 1개" 규칙에 세지 않는다. 엔진이 적은 원인(`?` 내용)은 데스크톱 상태 줄에 보이지 않는다.
- `분석 시작`: 라벨은 동작 이름(`분석 시작`·`이어하기`)만 쓰고 `준비 필요`·`이어하기 불가`를 쓰지 않는다. 막혔을 때는 사유와 관계없이 옅은 회색 비활성 하나(Button의 disabled 변형)다. 이유는 상태 줄이 말하고(`aria-describedby`), 버튼은 `aria-disabled`로 두어 누르면 상태 줄로 포커스를 옮긴다. 필수 항목만 비었으면 버튼을 켜 두고, 누르면 상태 줄에 `필수 항목이 비어 있습니다`와 남은 칸 목록을 보인 뒤 첫 빈 칸으로 포커스를 옮긴다. 목록은 채우는 대로 줄고 다 채우면 사라진다.
- 접근성: 상태 줄은 늘 마운트된 `role="status"`(`aria-atomic`) 하나이고, 동작 줄 전체에 `aria-live`를 걸지 않는다. 배경 확인은 내용이 바뀔 때만 알린다.
- 응답 없음: 연결된 뒤 확인 회차마다 45초 안에 준비 확인이 끝나지 않으면 `LMO 회의록 연결이 응답하지 않습니다`, `잠시 뒤 다시 확인해 주세요.`, `다시 확인`이다. `다시 확인`은 연결을 확인한 뒤 준비 확인을 다시 시작한다. 다시 연결하면 타이머를 새로 둔다. 데스크톱은 앱을 연 뒤 45초 동안 응답이 없으면 `분석 기능이 아직 준비되지 않았습니다`, `첫 실행은 몇 분 걸릴 수 있습니다.`, `문제 해결`이고, 그 전에는 회색 스피너와 `분석 기능 준비 중`이다. 데스크톱·기본 개발 UI도 웹과 같은 확인 회차별 45초로 센다. 첫 회차는 작성 화면이 열릴 때(앱을 열 때와 새 회의록을 열 때마다) 시작하고, 엔진의 모델 상태 응답·창 포커스·설정 변경·분석 종료 때 새로 센다. 경고 뒤에도 준비 확인은 10초마다 계속 돌아 엔진이 답하면 경고가 저절로 풀린다. 그래서 데스크톱 경고에는 `다시 확인` 없이 `문제 해결` 하나만 둔다. 준비 상태 확인 실패에서 누른 `다시 확인`이 답을 못 받으면 확인을 다시 돌린다. 예전 `readinessTimedOut`(엔진이 아예 답하지 않을 때만 켜지고 `/api/health` 응답으로만 꺼짐)은 없앴다.
- 모델: 필요한 모델이 없으면 `모델을 받아야 분석할 수 있습니다`, 모델 목록(`음성 인식, 참석자 구분`), `모델 받기`다. GPU 문제가 함께 있어도 모델을 먼저 말하고, 모델이 없는 동안 10초 간격으로 다시 확인한다. `모델 받는 중` 진행 표시는 이번 범위에서 뺀다. 작성 화면이 받기 진행 데이터를 읽게 되면 다시 판단한다.
- 입력 단계(③, Figma `16:1012`): 준비가 끝난 뒤 순서는 고른 이어하기 기록 불가 → 같은 파일 진행 중 → 다른 분석 진행 중 → 파일 길이 → 이어하기 파일 선택·다른 파일 → 필수 항목이다. 앞의 둘은 "다른 분석 진행 중"의 구체적인 형태라 먼저 말한다. 문구는 `진행 중인 분석이 있습니다`·`끝나면 새 회의록을 분석할 수 있습니다.`(취소 정리 중도 같음, 버튼 없음), `같은 파일 분석이 이미 진행 중입니다`·`먼저 상태를 확인해 주세요.`·`상태 확인`, `파일이 2시간을 넘습니다`·`2시간 이하의 음성·영상 파일을 선택해 주세요.`·`다른 파일 선택`, `이어서 분석할 파일을 선택해 주세요`·파일 이름·`파일 선택`, `선택한 파일이 다릅니다`·`<파일 이름> 파일을 다시 선택해 주세요.`·`다른 파일 선택`, `이전 분석을 이어서 진행할 수 없습니다`·`새 분석으로 시작할 수 있습니다.`(다른 실행에서 진행 중이면 `진행이 끝나거나 중단된 뒤 이어갈 수 있습니다.`)다. 고른 기록의 분석이 다른 실행에서 끝나 회의록이 저장됐으면 다시 분석하라고 하지 않고 안내색 `이 분석은 이미 끝났습니다`·`결과는 회의록에서 확인해 주세요.`다. 필수 항목 목록은 화면 읽기 순서(회의 제목, 일시, 회의 목적, 영상·음성 파일)이고 빈 칸이 `aria-describedby`로 가리킨다. 창 포커스 같은 배경 기록 확인 중에는 마지막 판단을 유지해 `이전 분석을 이어서 진행할 수 없습니다`로 깜빡이지 않는다.
- 구현 때 확인할 것: 브라우저 차단(권한 거부) 뒤 `다시 확인`만으로 풀리는지는 첫 구현 조각에서 실제 Chrome으로 확인한다. 새로고침이 필요하면 버튼을 `새로고침`으로 바꾸고 입력 내용이 남는지 함께 본다.
- 엔진 이름은 웹 `LMO 회의록 연결`, 데스크톱 `분석 기능`이고, 데스크톱의 다시 설치 대상은 `LMO 회의록`이다.
- 분석 실패 문구는 원문(영어, `서버 응답 오류: 500`, fetch 오류)을 그대로 보여 주지 않고 `describeAnalysisError`(`apiError.ts`)로 원인과 사용자 문장으로 바꾼다. 원인은 엔진 오류의 `code`(`insufficient_memory`, `insufficient_storage`, `unsupported_media`, `analysis_stage_timeout` 등)를 먼저 보고, 없으면 원문 패턴으로 가른다. 우리가 만든 한글 메시지는 그대로 둔다.
- GPU 실행 오류(`gpu_unavailable`: cuBLAS·cuDNN·드라이버)와 GPU로 분석하던 중의 메모리 부족은 다시 시도해도 같은 결과라서, 실패 화면의 주 버튼을 `분석 장치 설정`으로 하고 CPU로 바꾸라고 안내한다(`다시 시도`는 보조). GPU 메모리 부족은 첫 문장을 `GPU 메모리가 부족해 분석을 마치지 못했습니다.`로 쓴다.
- 실패 카드의 주 버튼은 원인을 따른다: 대화록이 이미 저장됐으면 `결과 보기` 하나만 두고 문장은 남은 단계와 원인을 말한다(`대화록은 저장했습니다. 메모리가 부족해 참석자 구분을 마치지 못했습니다.`), 연결 끊김은 `다시 확인`(웹)·`문제 해결`(데스크톱), 읽을 수 없는 파일은 `다른 파일 선택`, 메모리·저장 공간·시간 초과·그 밖은 `다시 시도`다. 원인 문장이 다시 시도 전에 할 일(다른 프로그램 닫기, 공간 확보)을 말한다. 실패 카드는 사용자가 버튼을 누를 때까지 남고, 창 포커스나 자동 연결 확인으로 사라지지 않는다. Windows가 한국어로 낸 OS 오류(`[WinError 2] …`)나 엔진 예외 원문은 한글이어도 그대로 보이지 않는다.
- 분석 스트림이 시작되기 전 준비 단계(설정·연결·이어하기·저장 공간 확인)에도 `중지`가 있고, 누르면 바로 입력 화면으로 돌아간다(이어하기 기록 없음). 준비 요청은 15초 안에 답이 없으면 시간 초과로 실패한다(WR-6).
- 실패는 상세 화면의 분석 상태 영역에 원인과 복구 동작을 둔다. 회의 제목은 진행·실패·완료 동안 같은 자리에 유지한다. 일시 알림(중지·취소·삭제·새 분석)은 토스트로만 알리고 인라인 배너로 다시 띄우지 않는다.
- 로고는 분석 완료 안내가 남아 있으면 새 회의록을 새로 열고, 분석 중이면 진행 화면을 보여 준다.
- 대화록 동작 버튼(2026-10-21): 보이는 문구는 `복사`·`대화록`·`편집`으로 짧게 쓴다. 기존 편집용 복사·대화록 파일 저장·편집 동작은 유지하고, 다운로드의 툴팁과 화면 낭독기 이름은 저장 범위와 형식을 설명한다.
- 결과에서 참석자 구분을 따로 실행할 때도 기존 `처리 상태` 공간 안에서 진행률·경과·예상 시간과 중지 기호 하나를 표시한다. 별도 진행 패널로 제목·탭·검색·도구를 밀지 않는다. 중지 선택을 명시적으로 열 때만 안내가 늘어난다. 실행→중지 선택→계속의 키보드 초점을 이어 주고, 완료 때 진행 제어에 초점이 남아 있으면 제목으로 돌려준다. 본문으로 이동해 읽는 중이면 완료가 초점과 읽기 위치를 빼앗지 않는다.
- 분석 준비·진행·완료·결과 재열기(2026-10-21 사용자 결정): 기존 `MeetingHistory` 상세 화면 하나를 재사용한다. 입력한 회의 정보와 선택한 보고 양식을 이어서 보여주고, 제목·속성·대화록/기록 정리/보고서 탭·검색·동작 줄의 위치를 유지한다. 준비 중 미리보기는 메모리에만 있고 저장된 결과로 등록하지 않는다. 선택한 「속성 통합」 시안처럼 제목·회의 정보·처리 상태를 옅은 1px 테두리 하나로 묶는다. `처리 상태` 속성의 144px 공간에서 진행률·중지 기호·완료 표시를 바꾸며, 별도 완료 안내 카드와 `결과 보기` 단계를 두지 않는다. 기존 96px에서는 참석자 구분 대기와 음성 보관 안내가 함께 있을 때 마지막 줄이 잘려, 운영 실음성 검증 후 모든 단계에서 같은 높이로 늘렸다. 소요 시간·파일 메타정보·보관 관련 안내는 회의록에 저장해 재열기에도 유지한다. 원본 파일 행은 형식·크기·길이처럼 확보한 메타정보만 보이고 전체 파일명은 도움말로 남긴다. 참석자는 한 줄에서 줄임표를 쓰되 인원수 버튼은 항상 보이며 누르면 전체 이름을 펼친다. 중지 기호는 진행 막대와 같은 청록색·중앙 높이를 쓰고 기호에만 작은 애니메이션을 적용한다(동작 줄이기 설정을 따른다). 생략·보류 안내도 같은 상태 공간에 둔다. 중지 선택이나 오류 복구를 펼친 경우에는 필요한 만큼 높이가 늘 수 있다. 분석 중 결과를 바꾸는 동작은 잠그고, 완료 뒤 편집과 미저장 변경 보호를 정상 적용한다. 다른 회의록을 보는 중 끝난 분석은 현재 화면을 바꾸지 않는다. 사이드바 분석 카드는 다른 회의록을 볼 때 돌아오는 입구로만 표시한다.
- 긴 회의록의 `맨 위로`(2026-10-21): 현재 상세 내용이 작업면 높이의 두 배를 넘고 한 화면 이상 내려왔을 때만 작업면 우측 하단에 화살표 버튼을 둔다. 기존 작업면 스크롤을 사용하며 짧은 회의록과 맨 위에서는 표시하지 않는다. 대화록·기록 정리·보고서의 길이 변경, 검색, 창 크기, 다른 회의록 열기를 반영한다. 누르면 회의 제목으로 키보드 포커스를 옮기고 맨 위로 돌아간다. 동작 줄이기 설정에서는 부드러운 이동을 생략한다. 상단 정보 전체를 스크롤에 붙여 본문 공간을 차지하게 하지는 않는다.
- 보고서 탭의 상태 안내(생성 중 > 오류 > 막힘 > 실패 > 생성 안내)는 본문 위 자리가 고정된 한 줄에 하나만 보여 생성을 시작하거나 끝내도 본문이 움직이지 않게 한다. "이전 기준으로 생성된 보고서" 안내는 보고서 머리에 두고 생성 중에는 숨긴다. 기록 정리 탭도 command bar 아래에 같은 고정 줄(정리 중 > 오류)을 둔다. 진행 중에는 경과 시간을 붙이되 화면 낭독기에는 읽히지 않게 하고, 정리·생성 버튼은 최소 폭을 둬서 `정리`→`정리 중`→`다시 정리`로 바뀌어도 옆 선택칸이 움직이지 않는다.
- 기록 찾기(④): 880px 가운데 열, 제목 26px. 종류 필터는 밑줄 탭(`role="group"`, `aria-pressed`)이고 결정·할 일·회의록 표시는 상태색이 아닌 회색 태그와 표시점 모양(결정 청록, 할 일 진회색, 회의록 빈 점)으로 구분한다. 검색·기간·종류 필터는 상자 없이 제목 아래에 두고, 결과 카드는 테두리만 쓰며 hover 때 옅은 배경과 청록 테두리로 바뀐다(떠오르는 움직임 없음).
- `참석자 구분` 설정은 설정 화면이 단일 소유자이며, 분석 시작 직전 최신 설정값을 요청에 쓴다.
- 설정은 현재 작업면 위의 modal overlay이므로 열고 닫을 때 아래 작업면과 스크롤 위치를 바꾸지 않는다.

## 핵심 용어

- `회의 요약`: 분석 후 핵심 내용, 주요 주제, 할 일을 보여주는 영역
- `대화록`: 참석자, 시간, 문장을 함께 보여주는 영역
- `음성 파일`: 음성 파일과 영상 파일을 모두 포함하는 업로드 표현. 단, 새 회의록의 업로드 영역 제목은 영상도 받는다는 점을 바로 알리도록 `영상·음성 파일`로 쓴다. 영상도 분석 대상이지만 사용자는 최종적으로 음성을 분석한다고 이해한다.
- `참석자 구분`: 누가 말했는지 자동으로 나누는 분석 옵션

- `page-title`: 새 회의록·분석 진행·기록 찾기의 26px 화면 제목 (회의 상세 제목은 문서 제목이라 30px로 따로 둔다)
- `icon-badge`: 청록 옅은 원 안의 40px 아이콘 (업로드, 분석 중 파일, 이어서 할 분석)
- `--rail-content`(55rem): 모든 작업면(회의 상세, 새 회의록, 분석, 기록 찾기)이 함께 쓰는 열 최대 폭 토큰. 화면 파일에서 열 폭을 숫자로 다시 쓰지 않는다.
- `btn-ghost`, `icon-button`: 배경 없는 보조 동작과 아이콘 전용 버튼
- `input-field`, `select-field`: 텍스트 입력과 선택 컨트롤
- `settings-dialog`, `floating-panel`, `menu-panel`: 모달, 팝오버, 메뉴 표면
- `tab-list`, `tab-button`, `tab-button-active`: 탭 UI
- `sidebar-section-header`, `sidebar-section-action`: 사이드바 구역 이름과 구역 동작 버튼
- `summary-block`: 요약 본문
- `topic-chip`: 주요 주제 태그
- `speaker-turn`, `speaker-meta`: 대화록 행
- `detail-inline-note`, `detail-help-button`, `detail-control-card`: 상세 화면 보조문, 도움말, 입력 제어 묶음
- `speaker-label-panel`, `speaker-summary-*`: 참석자 이름 변경과 참석자별 정리
- `status-note`: 짧은 안내 및 주의 문구
- `resume-draft-card`, `resume-drafts-panel`, `sidebar-resume-draft-button`: 이어하기/이어서 할 분석

## 버튼 문구 규칙

- 버튼은 동작만 짧게 쓴다. 가능하면 `정리`, `저장`, `취소`, `연결`, `복원`, `선택`, `숨기기`처럼 2~4음절 중심으로 유지한다.
- 버튼에 설명을 넣지 않는다. 이유나 결과는 버튼 아래 보조문이나 상태 배너로 분리한다.
- 같은 동작을 여러 화면에서 반복할 때는 같은 문구를 유지한다.
- 사용자가 내부 구현을 알 필요가 없는 버튼에는 `AI`, 모델명, 서버 용어를 넣지 않는다.

## 상태 표시 규칙

- 완료 상태는 짧은 텍스트보다 아이콘으로 먼저 보여준다.
- 진행 중 상태는 스피너와 짧은 현재형 문구로 표시한다. 예: `정리 중`, `저장 중`, `확인 중`
- 주의나 재실행 필요 상태는 한 단어 또는 짧은 구로 표시한다. 예: `원본 필요`, `대화록 필요`, `수정 필요`
- 복사, 저장, 완료처럼 즉시 조치할 필요가 없는 일시 알림은 토스트나 고정 오버레이로 보여주고, 인라인 배너로 본문 레이아웃을 밀지 않는다.
- 인라인 배너는 오류, 경고, 복구 안내, 필수 설정처럼 사용자가 읽고 다음 행동을 결정해야 하는 지속 상태에만 쓴다.
- 성공/실패 후 안내 문구는 한 문장으로 끝낸다. 두 문장 이상 설명이 필요하면 별도 도움말로 분리한다.
- 모델 받기 진행 상태는 진행률, 남은 시간, `중지` 버튼만 간결하게 보여준다. 완료 배너나 긴 내부 상태 문구로 레이아웃을 밀지 않고, 준비 확인이 끝나면 체크 아이콘으로 표시한다.

## 포커스와 표면 규칙

- 키보드 포커스는 브라우저 기본 외곽선 대신 `--focus-ring-color`와 `--focus-ring-soft`를 쓴다.
- 버튼과 탭은 2px 외곽선, 입력과 선택 컨트롤은 테두리와 부드러운 링 조합을 쓴다.

## 회의 요약 / 대화록 화면 규칙

- 섹션 제목은 결과 이름만 쓴다. 예: `정리`, `대화록`, `주제별 정리`
- 결과 안에는 결과, 상태, 동작을 분리해서 배치한다. 설명 문구를 반복하지 않는다.
- 주제별 정리, 참석자별 정리, 참석자 이름 변경처럼 반복 사용되는 기능은 짧은 보조문 한 줄만 둔다.
- 빈 상태 문구는 무엇이 없는지와 다음 행동만 남긴다. 예: `주제별 정리 내용이 없습니다. 대화록을 확인해 주세요.`
- `대화록`, `기록 정리`, `보고서`는 3개의 산출물 탭으로 유지한다. 각 탭의 액션은 탭 본문 상단 command bar에 모은다.
- 대화록 발화 행은 화자, 시간, 상태 배지, 발언 내용을 분리해 긴 회의에서도 빠르게 훑을 수 있게 한다. 상세 콘텐츠 폭이 40rem 이상이면 `시작 시간 | 화자(+배지) | 발언` 한 행 3열로 둔다. 끝 시간은 title과 화면 낭독용 텍스트로만 제공한다. 좁은 폭에서는 `시간·화자` 줄 아래에 발언을 둔다.
- 긴 대화록은 발화마다 카드와 본문 버블을 중첩하지 않는다. 화자 색은 작은 식별 신호로 제한하고, hairline 구분선과 일관된 행 간격으로 하나의 읽기 목록을 만든다.
- 기록 정리의 `정리 기준`, 보고서의 `보고 양식`은 각 탭의 생성/저장 버튼과 같은 줄에서 다룬다.
- 기록 정리 작업 줄(2026-10-22): 정리 종류는 첫 줄 왼쪽에 두고, 다음 줄 왼쪽은 `정리 기준`과 `정리 기준 관리`, 오른쪽은 정리 실행과 `파일 저장`으로 묶는다. 기본 기준은 `기본 정리`로 표시한다. 좁은 본문에서 묶음 단위로 줄바꿈하며 탭과 작업 줄 시작 위치를 유지한다. 요약 프로그램 준비 응답은 실패가 아닌 경고와 명시적 재시도 안내로 표시한다. 새 결과는 `not_started`, 기존 완료 결과는 `completed`로 보존하고, 준비 완료 확인 시 대기 안내를 지운다. 실제 생성 실패는 오류 상태로 남긴다. 상태 안내가 있을 때 빈 결과 본문에 처음 실행하라는 문장을 중복하지 않는다. `파일 저장`은 전체 요약·주제별·참석자별 등 저장할 정리 내용이 하나라도 있으면 가능하며, 생성 중에는 잠근다. 저장 범위는 계속 기록 정리 전체다.
- `주요 주제`는 화면·기록 찾기·모든 내보내기에서 한 규칙을 쓴다: 주제별 정리가 있으면 그 제목만, 없으면 요약 주제를 보여 준다. 제목 앞뒤 공백을 제거한 뒤 브라우저 지역 설정과 무관한 소문자로 비교하며, 처음 나온 표기와 순서를 유지한다. `Maße`/`Masse`처럼 철자가 다르거나 제목 안쪽 공백이 다른 항목은 합치지 않는다. 원본 제목·주제 본문·저장 데이터는 바꾸지 않는다(공통 함수 `getDisplayTopics`, 백엔드 `pipeline/summary_display.py`). 화면에서는 `topic-chip` 한 줄로 보이고, 주제별 정리가 있는 칩을 누르면 그 주제로 이동한다.
- 보고서 양식은 보고서 생성 단계에만 적용하고, 기본 기록 정리 프롬프트와 섞지 않는다.
- 기록 정리 탭의 모델 안내는 사용자가 할 일이 있을 때만 둔다. 요약 모델이 없으면 `모델 필요` 경고와 `모델 준비`를 보이고, 정리를 누르면 저절로 시작되는 요약 프로그램 상태는 고정 안내로 보이지 않는다. 정리·보고서 생성이 모델이나 요약 프로그램 문제로 실패하면 그 탭의 상태 줄에 `모델 준비`를 붙인다.
- 상세의 오류는 일어난 자리에 둔다(2026-10-18 결정, 점검 4.3-1): 기록 정리·보고서는 탭의 고정 상태 줄, 대화록 탭의 저장·복사·파일 저장 오류는 command bar 아래 한 줄(오류가 있을 때만 생기고 탭·command bar는 움직이지 않음), 회의 정보·음성 저장·참석자 구분 오류는 속성 행 아래 한 줄이다. 셸 맨 위 배너는 회의록을 불러오지 못했을 때만 쓴다. 주 작업은 저장됐고 동기화·파일 갱신만 못 한 경우는 경고색이고 `저장 내용은 반영됐지만`으로 시작한다. 원인을 모르는 생성 실패는 `잠시 뒤 다시 정리해 주세요`처럼 다시 하기만 말하고 모델을 짐작하지 않는다(모델·요약 프로그램이 원인일 때만 그 문장과 `모델 준비`). 예약 줄은 늘 마운트된 polite live 영역이고, 오류가 있을 때만 생기는 줄은 `alert`(오류)·`status`(경고) 역할로 알린다. 다른 탭을 보는 동안 끝난 생성이 실패하면 같은 문장을 토스트로 한 번 알리고, 그 탭의 줄은 실패를 계속 보인다. 문장은 `toUserFacingError`로 "무엇을 못 했는지 + 원인별 다음 행동"을 쓰고 `Failed to fetch`·영어 원문·JSON 본문을 보이지 않는다.

## 설정 화면 기준

- 설정 항목이 적을 때는 별도 설정 사이드바 없이 상단 탭을 유지한다. 카테고리가 늘어 탐색 비용이 생길 때만 좌측 내비게이션으로 바꾼다.
- 일반 설정은 `파일`, `분석`, `보관`, `문제 해결`처럼 사용 목적에 따라 한 열로 묶는다.
- `재시작`은 데스크톱 앱에만 있다. 웹의 설정·모델 상태 오류는 `재시작`을 가리키지 않고 "LMO 회의록 연결이 실행 중인지 확인" 문장과 `다시 확인`을 쓴다(SB-2). 자동으로 다시 확인한다는 문장은 한 번만 쓴다.
- `문제 해결`의 `재시작`은 설정을 불러오는 중에도 누를 수 있다. 엔진이 응답하지 않을 때가 바로 재시작이 필요한 때이기 때문이다. 재시작하면 그전에 시작된 설정 읽기 결과는 버린다. 작성 화면의 `문제 해결`로 열면 이 영역으로 한 번 스크롤하고 포커스를 `재시작`에 둔다.
- 토글 설정은 제목과 설명을 왼쪽에, 스위치를 오른쪽에 둔다. 모든 항목을 독립된 회색 카드로 만들거나 2열 카드 그리드로 나열하지 않는다.
- 설정 저장은 즉시 반영을 기본으로 하고, `저장 중`과 `저장됨` 상태가 주변 레이아웃을 움직이지 않도록 고정 공간을 둔다. 창을 바로 닫거나 재시작해도 저장 대기 중인 변경을 먼저 보낸다.
- 엔진 값을 받기 전(또는 재시작으로 다시 읽는 동안)에는 엔진 설정 컨트롤 대신 `불러오는 중`, 읽지 못하면 `불러오지 못함`을 보여 주고 조작을 막는다. 추측한 기본값을 그리지 않는다. `다운로드 형식`은 브라우저 저장값이라 엔진과 무관하게 바로 바꾸고 저장한다.
- 모델 탭은 관리 화면이므로 모델명을 보여 주되, 기본 제공 모델에는 `2B · 가볍고 빠름`처럼 쉬운 설명을 붙인다. 사용자가 직접 누른 상태 확인만 `확인 중`으로 보여주고, 자동 반복 확인·`최근 확인` 시간·중복 완료 안내는 고정 표시하지 않는다. 모델 상태를 받기 전에는 어떤 모델이나 요약 프로그램도 "없음"으로 단정하지 않고 받기 동작을 숨긴다. 회의 요약 `모델 선택`은 이 PC에 있는 모델만 고를 수 있고(나머지는 `받기 필요`로 비활성) 고르는 즉시 적용한다. 받기는 아래 목록에서 한다.
- 회의록 정리(2026-10-20, Figma `23-1079`): `일반 > 보관` 마지막 줄 `회의록 정리`의 `정리하기`는 설정 창 안에서 일반 페이지 자리를 정리 화면으로 바꾼다. 두 번째 창을 겹치지 않는다. 화면 위 `일반 설정` 링크로 돌아가면 포커스는 `정리하기`로 돌아간다.
  - `이 브라우저의 회의록` 카드: `기간`(전체·3개월·6개월·1년 지난 회의록)은 목록을 좁히기만 하고, 미리 고르지 않는다. 기간을 바꾸면 선택을 비운다. 머리 체크박스는 보이는 회의록 전체를 고르며 일부만 고르면 섞임 표시가 된다. 목록은 카드 안에서 스크롤해 아래 동작 줄(`선택한 N개 삭제`)이 늘 보이게 한다. 시각 기준은 사이드바와 같은 기록 시각이다.
  - 삭제는 브라우저 확인창으로 개수를 한 번 더 묻고 한 건씩 지운다. 모두 지우면 토스트만 띄운다. 일부가 남으면(분석 중, 엔진 오류) 동작 줄 문장 자리에 남은 이유를 적고, 남은 회의록은 선택한 채로 둔다. 엔진이 꺼져 있으면 사이드바 삭제와 같은 대기열 규칙을 쓴다.
  - `이 PC에만 남은 분석 파일` 카드: 엔진의 완료 분석(`GET /api/stored-analyses`) 중 이 브라우저의 회의록·이어하기 기록이 쓰지 않는 것의 개수와 용량을 보여 주고 `모두 삭제`를 둔다. 같은 PC를 다른 브라우저에서도 쓰면 그 회의록의 분석 결과도 지워진다고 카드와 확인창에서 말한다. 엔진이 꺼져 있으면 `…실행 중일 때 확인할 수 있습니다.`, 목록 기능이 없는 이전 엔진이면 `…업데이트하면 확인할 수 있습니다.`라고만 보여 주고 버튼을 숨긴다. 지우기는 기존 `DELETE /api/outputs/{jobId}`를 쓰므로 이전 엔진에서도 동작한다. 이 브라우저의 회의록을 읽지 못하면 남은 파일을 세지 않고 버튼도 두지 않는다(빈 목록으로 보면 PC의 모든 분석이 남은 파일이 된다).
  - 데스크톱 앱에서는 `이 앱의 회의록`·`이 앱에 저장된 회의록이 없습니다`라고 쓰고, 다른 브라우저 경고를 뺀다. 삭제가 진행되는 동안은 `일반 설정`으로 돌아가기, 탭 전환, 설정 닫기(Esc·닫기 버튼)를 막아 남은 회의록 안내를 놓치지 않게 한다.
- 분석 탭은 기본값을 유지하되 필요할 때 조정하는 옵션만 둔다. 기능 없는 정보 탭은 두지 않는다.

## 피해야 할 표현

- 사용자 화면에서 특정 모델명으로 기능을 설명하지 않는다(설정 모델 관리 화면은 예외).
- 첫 화면 제목 위에 중복 분류 라벨을 고정 노출하지 않는다.
- 섹션 제목 앞에 정보 없는 번호 원형이나 장식 기호를 붙이지 않는다.
- `기본값 저장`처럼 현재 컨트롤의 보조 설명을 별도 텍스트로 반복하지 않는다.
- `SSE`, `FastAPI`, `diarization pipeline` 같은 구현 용어를 일반 화면에 노출하지 않는다.
- 반복 화면에 긴 사용 설명을 고정 배치하지 않는다.
- 긴 문장을 버튼 안에 넣지 않는다.
- 같은 뜻의 안내문을 섹션 안에서 반복하지 않는다.
- 상태 설명과 동작 설명을 한 문장에 같이 묶지 않는다.

## 색상 사용 규칙

- 화면 컴포넌트에서 `bg-blue-*`, `bg-red-*`, `bg-amber-*`, `text-blue-*`, `border-red-*` 같은 원시 색상 유틸을 직접 조합하지 않는다.
- 상태 안내는 `StatusBanner`와 `ProgressBar`를 우선 쓴다.
- 상태 색상은 `index.css`의 semantic status token을 기준으로 한다: `info`, `warning`, `error`, `success`, `neutral`.
- 버튼, 카드, 메뉴, 빈 상태처럼 반복되는 UI는 색상/테두리/hover를 화면에서 직접 만들지 않고 공통 클래스나 typed component prop으로 지정한다.
- 컴포넌트 호출부에서는 배치, 간격, 반응형 정도만 조합하고 색상 결정은 디자인 시스템에 둔다.
- 참석자 구분처럼 여러 색이 필요한 경우에는 예외적으로 데이터 구분 팔레트를 쓰되, `speaker-*` 계열 공통 클래스 안에서만 정의한다.
