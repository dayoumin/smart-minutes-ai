보고서 저장 수동 QA

자동 테스트는 HWPX zip/XML, DOCX XML, Markdown 본문 구조까지만 확인합니다. 실제 Word와 한글 뷰어에서 열리는지, 한글 서식과 문단 간격이 제출용으로 읽히는지는 이 체크리스트로 사람이 확인합니다.

범위

  • 보고서 탭의 보고서 저장 결과물만 우선 확인합니다.
  • DOCX는 Microsoft Word 기준으로 열기, 메타 표, 제목 계층, 한글 폰트 표시를 봅니다.
  • HWPX는 한글 또는 HWPX 뷰어 기준으로 열기, Preview 본문, 섹션 번호, 문단 줄바꿈을 봅니다.
  • MD는 사람이 읽는 보조 산출물이므로 보고 양식명, 섹션 순서, 참고 섹션 보존만 확인합니다.

샘플

샘플은 커밋하지 않는 임시 폴더에 생성합니다.

& 'C:\Users\User\AppData\Local\Programs\Python\Python311\python.exe' scripts\generate_report_export_qa_samples.py
파일 목적 확인 도구
.tmp\report_export_qa\report_scope.docx 보고서 전용 DOCX 서식 Microsoft Word
.tmp\report_export_qa\report_scope.hwpx 보고서 전용 HWPX 열기와 본문 표시 한글 또는 HWPX 뷰어
.tmp\report_export_qa\report_scope.md 보고서 전용 Markdown 구조 텍스트 편집기
.tmp\report_export_qa\full_scope.md 전체 회의록 저장 시 보고서와 대화록 공존 확인 텍스트 편집기

체크리스트

공통

  • 파일명이 열기 가능한 문자만 포함하고, 보고서 파일은 보고서 목적이 식별됩니다.
  • 문서 상단에 제목, 원본 파일, 처리 일시, 회의 목적이 보입니다.
  • 보고 양식명이 LMO 심사 보고 양식으로 보이며 현재 선택 양식과 섞이지 않습니다.
  • 섹션 순서는 검토 배경, 주요 검토, 결정사항, 후속 조치, 참고입니다.
  • 참고 섹션은 양식 밖 섹션을 보존하는 용도로 읽히고, 본문이 임의로 다른 섹션 제목 아래 들어가지 않습니다.

DOCX

  • Word에서 경고 없이 열립니다.
  • 한글 본문이 깨지지 않고 맑은 고딕 계열로 표시됩니다.
  • 문서 정보 표의 왼쪽 라벨과 오른쪽 값이 잘리지 않습니다.
  • 제목 1/제목 2 계층과 본문 간격이 과도하게 벌어지지 않습니다.
  • 불릿 문단과 긴 문장이 페이지 폭 안에서 자연스럽게 줄바꿈됩니다.

HWPX

  • 한글 또는 HWPX 뷰어에서 열기 오류가 없습니다.
  • Preview와 본문에 같은 섹션 제목과 내용이 보입니다.
  • 번호 체계가 1.1, 1.2처럼 보고서 섹션 안에서 자연스럽게 보입니다.
  • 빈 줄, 불릿, 긴 고유명사가 본문 영역 밖으로 밀리지 않습니다.
  • 문서가 열리지만 서식이 단순한 경우는 개선 필요로 남기고, 열기 실패는 결함으로 승격합니다.

완료 기준

  • DOCX와 HWPX가 각각 실제 뷰어에서 열립니다.
  • 보고 양식명, 섹션 순서, 참고 섹션이 자동 테스트 기대와 일치합니다.
  • 서식 문제가 사용자가 제출 전에 반드시 고쳐야 할 수준이면 결함 또는 TODO로 승격합니다.
  • 단순한 시각 개선 후보는 이 문서의 증거 기록에 남기고 다음 보고서 서식 개선 작업으로 분리합니다.
