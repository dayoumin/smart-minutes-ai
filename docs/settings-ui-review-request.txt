LMO 회의록 설정 UI — 집에서 재개 / 다른 AI 검토 요청 (2026-10-29)

사용자 목표
설정창을 내용에 맞게 줄이고 여백/정렬을 자연스럽게 한다. 받기·중지 상태 전환에서 제목·검색·조작 위치가 흔들리지 않아야 한다. 새 AI 모델 받기와 문의는 아이콘+hover/키보드 설명을 사용하며 중지 뒤 이어받기와 설정·모델 보존을 유지한다.

현재 상태
실제 Settings.tsx와 제품 CSS를 Storybook에 연결했다. 기본 높이613px, 최대760px, 짧은 확인 화면은 내용에 맞게 줄고 낮은 창은 본문만 스크롤한다. 머리글·본문 좌우24px, 본문 상하20px, 그룹 간20px/제목 간8px, STT 상태 공간84px와 조작 최소88px, 모델 행68px/두 행136px를 사용한다. 음량 안내는 성공 저장 후 한 번 표시하고 위쪽을 우선한다.

확인된 P2 — 아직 수정하지 않음
1. 키보드 초점 유실
   준비 상태에서 gemma4:e4b AI 모델 받기에 초점→Enter 실행. 중지 조작이 보일 때 document.activeElement는 BODY이고 다음 Tab은 문의 연락처 보기로 간다. TooltipIconButton이 일반 button으로 교체되는 시점에 기존 DOM 버튼이 제거되며 초점 복구가 없다.
   같은 버튼 DOM 유지 또는 실행 당시 초점만 새 중지 조작으로 복구하는 방안을 검토한다. Enter/Space·Tab/Shift+Tab·마우스 동작을 함께 검사한다.
2. 이어받기 버튼/아이콘 이동
   1360×900 모의 화면 실측: 받기/중지 x966, 폭32px. 이어받기 x906.515625, 폭91.484375px. 오른쪽 끝은 같지만 왼쪽 경계는59.48px, SVG 아이콘 중심은54.48px 왼쪽으로 이동한다.
   같은 크기 조작+설명 또는 일정한 조작 공간 등으로 의미 전달과 위치 안정성을 함께 해결한다. 긴 이어받기 글자를 없애는 것만으로 사용자가 다음 행동을 놓치지 않는지도 판단한다.

검사 공백
기존 check-storybook.mjs는 오른쪽 끝과 클릭 동작만 확인해 두 문제를 잡지 못했다. 통과한 검사와 결함 없음은 다르다. 버튼/아이콘 기준점과 키보드 실행 직후 초점을 실제로 검사해야 한다.

검토 범위
- desktop-app/src/Settings.tsx: renderAnalysisModelAction, 모델 행의 받기/중지/이어받기 조건, 모달/초점, 음량 안내.
- desktop-app/src/components/common/TooltipIconButton.tsx 및 index.css의 settings/tooltip 규칙.
- desktop-app/.storybook, stories/settingsScenario.ts, Settings.stories.tsx, IconAction.stories.tsx.
- desktop-app/scripts/check-storybook.mjs와 simulate-settings-model-management.mjs의 controls 경로.
- 기준/검사 설명은 docs/design.md, docs/frontend-simulation-testing.md.
백엔드 worker·설치 프로그램·저장 형식·다른 화면의 전면 재설계로 확대하지 않는다. 현재 승인된2열 구조와 브랜드를 유지한다.

기존 검증과 한계
Windows Node22.22.2/Corepack pnpm10.33.2. 타입·변경 파일 lint·layout 검사·Storybook 생성,19개 모의 UI 검사와 별도 controls 저장/닫기/재열기 검사를 통과했다. 두 agent의 후속 검토와 메인의 좁은 모의 재현으로 위 두 P2를 확인했다. 1360×900/860×720의 일반 높이613px,860×540의508px 내부 스크롤, 페이지/짧은 확인/안내 가림/Docs 격리는 확인했다.
실제 Windows 실행 파일, 실제 엔진/모델 다운로드, 설치·재시작 복구, 스크린리더/브라우저 확대 검증을 완료했다는 뜻은 아니다. 새 frozen worker 포함·모델 전체 받기/요약·앱 재시작 뒤 중지 상태 복원은 기존 release QA에 남아 있다.

집 PC에서 준비
1. 기존 변경을 확인하고 깨끗할 때만 git pull --ff-only. 로컬 변경을 reset하거나 전역 설정을 덮어쓰지 않는다.
2. 기존 Node/pnpm과 의존성을 재사용한다. 없을 때만 corepack pnpm --dir desktop-app install --frozen-lockfile.
3. 포트를 확인한 뒤 corepack pnpm --dir desktop-app storybook (기본127.0.0.1:6011).
4. 좁은 검사: corepack pnpm --dir desktop-app typecheck, 변경 파일 eslint, storybook:build 후 storybook:check. 필요하면 SETTINGS_MODEL_SCENARIO=controls로 기존 회귀를 실행한다. 프로젝트 Playwright 캐시는 docs/frontend-simulation-testing.md를 따른다.

다른 AI에게 요청할 결과
A. 각 P1/P2의 파일/줄, 시작 상태→조작→결과, 사용자 영향, 근거와 최소 수정 방향.
B. 확정 결함과 아직 검증하지 못한 가설을 분리.
C. 선택적인 미감/개선은 차단 결함과 분리.
D. 두 수정의 회귀를 막는 최소 검사와 기존 기능 보존 조건.
자료에서 확인할 수 없는 코드를 없는 것으로 가정하지 않는다. 별도 지시가 없으면 검토만 하고 실행·파일 수정·외부 전송을 하지 않는다.

자료 공유 주의점
이 요청문과 소스/검사는 Git으로 공유한다. .tmp의 검토 ZIP·원본 화면·실측 JSON, releases의 EXE/패키지, 모델/환경/사용자 전역 지침은 Git에 포함하지 않는다. 집에서는 저장소의 실제 소스를 읽고 Storybook 화면을 재생성해 검토할 수 있다. 현재 인계는 공개 배포가 아니다.
